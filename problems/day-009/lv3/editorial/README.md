# 해설 — 끝없는 암호 띠

## 접근
구간 질의는 늘 그렇듯 **"앞에서부터 x글자 안에 `c`가 몇 번"** 을 구하는 함수 `F(x, c)`를 만들고 `F(r, c) - F(l - 1, c)`로 답합니다. 핵심은 `F`를 O(1)에 구하는 것입니다. `n = |s|`라 하면 앞 `x`글자는

- 완전한 조각 `q = x / n`개와
- 마지막 조각의 앞 `rem = x % n`글자

로 이루어집니다.

**관찰 1 — 조각 26개가 한 주기입니다.** `k`번 조각에서 글자 `c`가 되는 것은 원래 글자가 `(c - k) mod 26`인 자리입니다. `k`가 0부터 25까지 한 바퀴 돌면 원래 글자 26종이 각각 정확히 한 번씩 `c`로 바뀌므로, 조각 26개 묶음 안에서 `c`는 **정확히 `n`번** 나옵니다. 따라서 완전한 조각 `q`개 중 `q / 26` 묶음은 `(q / 26) × n`으로 한 번에 셉니다.

**관찰 2 — 남은 조각은 글자별 개수로 셉니다.** `s`에서 글자 `ch`가 나오는 횟수를 `cnt[ch]`라 하면, 남은 `q % 26`개의 조각(번호 `k = 0 … q%26 - 1`, 실제 번호는 26의 배수만큼 더해도 결과가 같으므로 작은 번호로 봐도 됩니다)에서 `c`의 개수는 `Σ cnt[(c - k) mod 26]`입니다. 많아야 25번 더합니다.

**관찰 3 — 마지막 조각의 일부는 접두 개수 표로 셉니다.** `pre[ch][i]` = `s`의 앞 `i`글자 중 `ch`의 개수를 미리 만들어 두면, 번호 `q`인 조각의 앞 `rem`글자 안의 `c`는 `pre[(c - q) mod 26][rem]`입니다. 이 표는 26 × (n + 1)개의 `int`로 약 20MB입니다.

세 부분을 더하면 `F(x, c)`이고, 질의마다 O(26)입니다.

## 주의할 점
- 질의마다 마지막 조각을 **직접 훑어서** 세면 질의 하나에 O(n), 전체 O(n × 질의 수) = 4×10^10 이라 시간 초과입니다. 접두 개수 표가 꼭 필요합니다. 조각 단위로 반복하는 풀이는 조각 수가 10^18 / n 이라 더 말할 것도 없습니다.
- `x`는 최대 10^18이므로 `q = x / n`, `(q / 26) × n` 모두 `long`입니다. `q % 26`은 `long`을 `int`로 바꿔 씁니다.
- `(c - k) mod 26`은 음수가 될 수 있으니 `((c - k) % 26 + 26) % 26` 또는 `Math.floorMod`를 쓰세요. `q`가 `long`이면 `(int) (q % 26)`으로 먼저 줄인 뒤 계산합니다.
- `l > r`인 질의가 있으므로 먼저 `min`, `max`로 정리합니다.
- 질의 문자열은 `split(" ")`으로 세 조각을 얻어 `Long.parseLong`으로 읽습니다. 20만 개 정도는 `split`으로 충분합니다.

## 복잡도
- 시간 O(26n + 26q) (q = 질의 수), 공간 O(26n)
