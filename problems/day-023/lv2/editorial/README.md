# 해설 — 이삿짐 상자 중 가장 무거운 것

## 접근
질의마다 쌓인 상자를 모두 훑어 최댓값을 찾으면, 상자 50만 개 위에서 질의 50만 번이면 2.5×10^11 번으로 시간 초과입니다. 최댓값을 변수 하나에 들고 있자니, 맨 위 상자를 내렸을 때 "그 다음으로 무거운 것"을 알 수 없습니다.

**최댓값 스택**: 상자 스택과 나란히 **"이 상자까지 쌓였을 때의 최댓값"** 을 쌓습니다.

- 올리기 `w`: 상자 스택에 `w`를, 최댓값 스택에 `max(w, 직전 최댓값)`을 넣습니다.
- 내리기: 두 스택에서 하나씩 꺼냅니다.
- 질의: 최댓값 스택의 맨 위가 답입니다. 비어 있으면 0.

맨 위 상자를 내리면 최댓값 스택의 맨 위도 함께 사라지고, 그 아래 값이 "남은 상자들만의 최댓값"이므로 항상 맞습니다.

## 주의할 점
- 상자 무게를 저장하는 스택은 사실 필요 없습니다. 최댓값 스택만 있어도 질의와 내리기를 처리할 수 있습니다 (모범 풀이도 하나만 씁니다).
- 질의 결과 개수를 먼저 세어 두면 `List` 없이 `int[]`를 바로 채울 수 있습니다.
- 100만 개 입력이므로 `ArrayDeque<Integer>`의 박싱 비용보다 `int[]` 스택이 확실히 빠릅니다.

## 복잡도
- 시간 O(n), 공간 O(n)
