# 해설 — 결재 서류 더미 뒤집기

## 접근
뒤집기 명령이 올 때마다 더미를 실제로 뒤집으면(`Collections.reverse` 등) 한 번에 O(n)이라, 서류 25만 장 위에서 뒤집기 12만 번이면 3×10^10 번으로 시간 초과입니다.

**덱(`ArrayDeque`)과 "뒤집힌 상태" 플래그 하나**면 충분합니다. 더미를 실제로 뒤집는 대신 "지금 어느 쪽 끝이 맨 위인가"만 기억합니다.

- `reversed = false`일 때 맨 위는 덱의 **뒤쪽**(`addLast`/`pollLast`)
- `reversed = true`일 때 맨 위는 덱의 **앞쪽**(`addFirst`/`pollFirst`)
- 뒤집기 명령: `reversed = !reversed` — O(1)

어느 쪽에서 넣고 빼든 덱은 양쪽 모두 O(1)이므로 모든 명령이 O(1)입니다.

## 주의할 점
- 서류를 올릴 때도 플래그에 따라 넣는 쪽이 달라야 합니다. 빼는 쪽만 바꾸면 틀립니다.
- 빈 더미에서 처리하면 `-1`을 **기록해야** 합니다(무시가 아닙니다). 빈 더미 뒤집기는 플래그만 바뀌고 결과에 영향이 없습니다.
- 종류 2, 3의 두 번째 값은 의미 없는 값이므로 읽지 마세요.

## 복잡도
- 시간 O(n), 공간 O(n)
