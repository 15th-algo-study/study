# 해설 — 항공 화물 운임표

## 접근
출발점이 0번 하나뿐이므로 모든 쌍을 구하는 플로이드–워셜(O(n³))은 필요 없습니다. n = 5,000이면 1.25 × 10^11번이라 시간 초과입니다. 게다가 n × n 거리표를 n번 처음부터 끝까지 훑어야 해서 메모리 읽기만으로도 오래 걸립니다.

한 출발점 최단 거리는 **다익스트라**입니다. 그래프가 인접 행렬로 주어지고 거의 모든 쌍에 간선이 있으므로, 우선순위 큐 없이 배열로 구현하는 O(n²) 다익스트라가 가장 간단하고 빠릅니다.

1. `dist[0] = 0`, 나머지는 INF. `done[]`은 모두 false.
2. n번 반복합니다.
   - 아직 확정되지 않은(`done == false`) 정점 중 `dist`가 가장 작은 `v`를 찾습니다. 그 값이 INF면 더 갈 수 있는 곳이 없으니 멈춥니다.
   - `v`를 확정하고, `fare[v][u] > 0`인 모든 `u`에 대해 `dist[v] + fare[v][u]`로 `dist[u]`를 줄입니다.
3. INF로 남은 공항은 -1입니다.

운임이 모두 양수라서, 확정되지 않은 정점 중 가장 가까운 정점은 다른 정점을 거쳐 더 짧아질 수 없습니다. 그래서 꺼내는 순간 확정해도 됩니다.

## 주의할 점
- `fare[v][u] == 0`은 "공짜"가 아니라 "직항 없음"입니다. 0을 그대로 간선으로 쓰면 틀립니다.
- `fare[i][i]`는 무시합니다. 0번의 답은 항상 0입니다.
- 간선이 n² = 2,500만 개라 이것을 리스트로 옮기거나 객체를 만드는 데만도 시간이 걸립니다. 행렬을 그대로 훑습니다.
- 최소 운임은 최대 4,999 × 10^9 ≈ 5 × 10^12라 `long`이 필요합니다. 운임 하나는 `int`에 들어가지만 두 개만 더해도 넘칠 수 있습니다.

## 복잡도
- 시간 O(n²), 공간 O(n)
