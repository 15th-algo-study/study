# 해설 — 전세 헬기와 산길

## 접근
헬기 이동을 간선으로 그대로 만들면 헬기장 `p`개마다 `p − 1`개씩, 모두 p² ≈ 4 × 10^10개라 만들 수조차 없습니다.

**관찰**: 헬기장 `i` → 헬기장 `j`의 요금 `takeoff_i + landing_j`는 "떠나는 쪽 요금"과 "내리는 쪽 요금"의 합으로 **나뉩니다**. 그러면 가상의 **하늘 정점 H**를 하나 추가해

- `town_i → H` : 비용 `takeoff_i` (헬기장 `i`에서 이륙)
- `H → town_j` : 비용 `landing_j` (헬기장 `j`에 착륙)

두 종류의 **한 방향** 간선만 두면 됩니다. `town_i → H → town_j` 경로의 비용이 정확히 `takeoff_i + landing_j`이므로 모든 헬기 이동이 표현되고, 간선 수는 헬기장 수의 2배뿐입니다. 산길(양방향 간선 2개씩)과 함께 정점 `n + 1`개 그래프에서 0번부터 다익스트라를 돌리면 답이 나옵니다.

`town_i → H → town_i`처럼 같은 헬기장에 내리는 경로도 생기지만, 비용이 0 이상이라 최단 경로에 도움이 되지 않으므로 문제없습니다.

## 다른 풀이
헬기는 한 번만 타면 충분합니다. 두 번 타는 경로 `i → j`, (걷기), `k → l`은 `i → l` 한 번으로 바꾸면 비용이 줄거나 같기 때문입니다. 그래서 0번과 `n − 1`번에서 다익스트라를 한 번씩 돌린 뒤
`min( 산길로만 간 거리, min_i(d0[town_i] + takeoff_i) + min_j(landing_j + dN[town_j]) )`
로 구해도 됩니다. (두 최솟값이 같은 헬기장에서 나오면 제자리 비행이지만, 그 값은 산길로만 간 거리보다 작을 수 없어 결과에 영향이 없습니다.)

## 주의할 점
- H → town 간선은 한 방향이어야 합니다. 양방향으로 넣으면 착륙료를 내고 이륙하는 잘못된 이동이 생깁니다.
- `takeoff`, `landing`이 0일 수 있으므로 가중치 0 간선이 생깁니다. 다익스트라는 음수만 아니면 정당합니다.
- 다익스트라 도중 헬기장 마을을 꺼낼 때마다 모든 헬기장을 갱신하면 O(p²)라 시간 초과입니다.
- 비용의 합은 최대 약 2 × 10^14라 `long`입니다.

## 복잡도
- 시간 O((n + m + p) log(m + p)), 공간 O(n + m + p)
