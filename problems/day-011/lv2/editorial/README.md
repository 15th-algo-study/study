# 해설 — 순이익이 딱 맞는 기간

## 접근
누적합 `P[i]` = 0번 날부터 `i-1`번 날까지의 합(`P[0] = 0`)이라 하면, 기간 `[l, r]`의 합은 `P[r+1] - P[l]`입니다. 그러므로 끝 날 `r`을 고정했을 때 조건은

> `P[l] = P[r+1] - target` 인 `l`(0 ≤ l ≤ r)의 개수

입니다. 앞에서부터 누적합을 계산하면서 "지금까지 나온 누적합 값이 몇 번씩 나왔는지"를 `HashMap<Long, Integer>`에 넣어 두면, 각 `r`에서 `map.get(P[r+1] - target)`이 바로 그 개수입니다.

순서가 중요합니다: 현재 누적합으로 **먼저 개수를 더한 뒤**에 현재 누적합을 맵에 넣어야 길이 0인 기간이 세어지지 않습니다. 맵에는 처음에 `P[0] = 0`을 한 번 넣어 둡니다.

## 주의할 점
- 손실(음수)이 있어서 "합이 커지면 왼쪽을 줄인다"는 투 포인터가 통하지 않습니다. 누적합 + 해시가 정석입니다.
- 모든 시작·끝 쌍을 확인하는 O(n²)은 50만 개에서 약 1.25×10^11 번이라 시간 초과입니다.
- 누적합은 최대 5×10^5 × 10^6 = 5×10^11이라 `int`를 넘습니다. `long`을 쓰고 맵의 키도 `Long`으로 두세요.
- 답도 최대 n(n+1)/2 ≈ 1.25×10^11이므로 `long`입니다 (예: 모두 0이고 `target = 0`).

## 복잡도
- 시간 O(n), 공간 O(n)
