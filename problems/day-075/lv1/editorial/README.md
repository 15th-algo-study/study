# 해설 — 골동품 양 끝 판매

## 접근
양 끝에서만 꺼내므로, 어느 시점이든 남아 있는 물건은 항상 **연속한 구간** `l..r`입니다. 그리고 구간 길이를 알면 오늘이 며칠째인지도 정해집니다. 이미 판 물건이 `n − (r − l + 1)`개이므로 오늘은 `d = n − (r − l + 1)`번째 시세(`rates[d]`, 0부터 셈)를 씁니다.

그러므로 "남은 구간"만으로 앞으로의 최선을 정할 수 있습니다(구간 DP).

- `best[l][r]` = 물건 `l..r`이 남아 있을 때, 이것들을 모두 팔아 얻는 금액의 최댓값
- `best[i][i] = values[i] × rates[n - 1]` (마지막 날에 파는 물건)
- `best[l][r] = max(values[l] × rates[d] + best[l+1][r], values[r] × rates[d] + best[l][r-1])`, `d = n − (r − l + 1)`

`best[l][r]`은 길이가 하나 짧은 구간만 참조하므로 **구간 길이 1, 2, …, n 순서로** 채웁니다. 답은 `best[0][n-1]`입니다.

## 주의할 점
- 매일 양 끝 중 싼 것(또는 비싼 것)을 파는 그리디는 틀립니다(예 #1). 시세가 들쭉날쭉하면 더 그렇습니다(예 #2).
- 매일 왼쪽/오른쪽을 모두 시도하는 재귀는 2^n가지라 n = 2,000에서 끝나지 않습니다. 같은 구간이 여러 경로에서 반복되므로 표에 저장합니다.
- `values × rates`는 최대 10^9, 합은 최대 2×10^12라 `long`이 필요합니다. 곱하기 전에 `(long)`으로 바꾸세요.
- 2,000 × 2,000 `long` 표는 약 32MB입니다. 길이 순서로 채우면 1차원 배열 하나로 줄일 수도 있습니다.

## 복잡도
- 시간 O(n²), 공간 O(n²)
