# 해설 — 두 탐험가의 경유지

## 접근
최장 공통 부분 수열(LCS)이지만, 일반 LCS 표는 20만 × 20만 = 4×10^10칸이라 시간 초과입니다. 이 문제에는 **"한 기록 안의 번호가 모두 다르다"** 는 특별한 조건이 있습니다.

**관찰**: 섬 번호가 `routeB` 안에서 유일하므로, 섬 `x`의 `routeB` 위치 `posB[x]`가 하나로 정해집니다. `routeA`에서 고른 섬들을 `routeA` 순서대로 나열했을 때, 이것이 `routeB`에서도 순서를 지키려면 **`posB` 값이 엄격히 증가**해야 합니다.

1. `routeB`의 각 번호 → 위치를 `HashMap`에 저장합니다.
2. `routeA`를 앞에서부터 보며 `routeB`에도 있는 섬만 골라 그 `posB` 값을 차례로 적습니다. 이 수열을 `seq`라 합시다.
3. 공통 항로 ↔ `seq`의 엄격 증가 부분 수열이 일대일로 대응합니다. 그러므로 답은 **`seq`의 LIS 길이**입니다.

LIS는 O(n log n)으로 구합니다. `tails[len]` = 길이 `len + 1`인 증가 부분 수열의 끝값 중 최솟값. 새 값 `x`마다 `tails`에서 `x` 이상인 첫 위치를 이분 탐색해 `x`로 바꾸고, 없으면 뒤에 붙입니다. `tails`의 길이가 답입니다.

## 주의할 점
- 일반 LCS DP(O(n × m))는 물론, `seq`에 O(n²) LIS를 쓰는 것도 n = 200,000에서 약 2×10^10번 비교라 시간 초과입니다.
- `posB`는 모두 다르므로 엄격 증가와 비엄격 증가가 같지만, 습관적으로 lower bound(이상인 첫 위치)를 쓰면 됩니다.
- 섬 번호가 10^9까지라 배열 인덱스로 쓸 수 없습니다. `HashMap`(또는 정렬 + 이분 탐색)으로 위치를 찾습니다.
- `routeB`에 없는 섬은 공통 항로에 들어갈 수 없으므로 `seq`에서 빼면 됩니다.

## 복잡도
- 시간 O((n + m) + n log n) (해시 평균), 공간 O(n + m)
