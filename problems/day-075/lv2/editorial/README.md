# 해설 — 선물 꾸러미 경우의 수

## 접근
"상품마다 고르거나 안 고르거나"이므로 0/1 배낭의 **경우의 수** 버전입니다. 다만 개수 조건(정확히 `k`개)이 하나 더 있으므로 표의 차원을 하나 늘립니다.

- `ways[c][s]` = 지금까지 본 상품 중 **`c`개를 골라 가격 합이 `s`** 인 방법의 수
- 처음에는 `ways[0][0] = 1` (아무것도 안 고름), 나머지 0
- 상품 `p`를 볼 때마다 이 상품을 고르는 경우를 더합니다:
  `ways[c][s] += ways[c-1][s-p]`

상품 하나를 두 번 고르지 않도록 **`c`를 큰 쪽에서 작은 쪽으로** 갱신합니다. 그러면 `ways[c-1][…]`는 아직 이 상품을 반영하기 전의 값입니다(1차원 0/1 배낭에서 무게를 큰 쪽부터 도는 것과 같은 이유).

답은 `ways[k][budget]`입니다.

## 주의할 점
- 덧셈마다 1,000,000,007로 나눈 나머지를 유지하세요. 두 값이 각각 10^9 + 7 미만이면 합은 `int` 범위(약 2.1×10^9) 안이지만, 더 큰 값을 더하면 넘칩니다.
- 순서를 따지지 않으므로 상품을 바깥 반복문에 둡니다. 상품을 안쪽 반복문에 두면 순서가 다른 같은 꾸러미를 여러 번 셉니다.
- 모든 조합을 직접 세면 C(100, 50) ≈ 10^29가지라 불가능합니다.
- `c`는 지금까지 본 상품 수와 `k` 중 작은 값까지만, `s`는 `budget`까지만 보면 됩니다. 연산 수는 최대 100 × 100 × 10,000 = 10^8 번입니다.

## 복잡도
- 시간 O(n × k × budget), 공간 O(k × budget)
