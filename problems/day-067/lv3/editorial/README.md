# 해설 — 녹음실 예약 고르기

## 접근
금액이 모두 같다면 끝나는 시각이 빠른 요청부터 고르는 탐욕이 통하지만, 여기서는 요청마다 금액이 달라서 탐욕이 틀립니다. 예를 들어 예 #2에서 10시간짜리 요청의 금액이 130이었다면, 끝이 빠른 [0, 5)부터 고르는 탐욕은 120을 얻지만 답은 130입니다. 그래서 DP를 씁니다.

요청을 **끝나는 시각 순으로 정렬**하고, `best[i]` = "앞의 `i`개 요청만 보고 고를 때의 최대 수입"이라고 합시다. `i`번째 요청(0부터 셈)을

- 받지 않으면: `best[i]`
- 받으면: `pay + best[p]` — `p`는 "끝나는 시각이 이 요청의 시작 시각 이하인 요청의 수"

이므로 `best[i + 1] = max(best[i], pay + best[p])`입니다. 끝나는 시각 순으로 정렬했으니 끝 시각 ≤ start인 요청은 정렬된 배열의 맨 앞 `p`개에 모여 있고, `best`는 개수가 늘수록 줄지 않으므로 `best[p]`가 "이 요청과 겹치지 않는 요청들로 얻는 최댓값"입니다.

`p`는 정렬된 끝 시각 배열에서 **이분 탐색**(upper bound)으로 O(log n)에 구합니다.

## 주의할 점
- 가장 단순한 DP는 각 요청마다 앞의 모든 요청을 훑어 겹치지 않는 것 중 최댓값을 찾는 O(n²)입니다. n = 30만이면 450억 번이라 시간 초과입니다. 뒤에서부터 훑다가 처음 만나는 겹치지 않는 요청에서 멈추는 방법도, 긴 요청이 많으면 결국 O(n²)이 됩니다.
- 끝 시각은 `start + duration`으로 최대 2 × 10^9라 `int`를 넘습니다. `long`으로 계산하세요.
- 끝 시각 = 다른 요청의 시작 시각이면 함께 받을 수 있으므로 "끝 ≤ start"(upper bound)로 셉니다. "끝 < start"로 세면 예 #2, #3이 틀립니다.
- 수입 합은 최대 2 × 10^14이므로 `long`입니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
