# [lv3] 녹음실 예약 고르기

녹음 스튜디오에 녹음실이 하나 있습니다. 예약 요청 목록 `requests`의 각 원소 `[start, duration, pay]`는 `start` 시각부터 `duration`시간 동안, 즉 `start` 이상 `start + duration` 미만인 시간에 녹음실을 쓰고 `pay`원을 내겠다는 요청입니다.

녹음실은 한 번에 한 팀만 쓸 수 있으므로 쓰는 시간이 겹치는 두 요청을 함께 받을 수 없습니다. 한 요청이 끝나는 시각에 다른 요청이 시작하는 것은 괜찮습니다.

받을 요청을 골라 얻을 수 있는 수입의 최댓값을 return 하도록 `solution` 함수를 완성해 주세요. 답이 `int` 범위를 넘을 수 있으므로 `long`으로 return 합니다.

## 제한사항
- 1 ≤ `requests`의 길이 ≤ 300,000
- `requests`의 원소는 `[start, duration, pay]` 형식입니다.
  - 0 ≤ `start` ≤ 1,000,000,000
  - 1 ≤ `duration` ≤ 1,000,000,000
  - 1 ≤ `pay` ≤ 1,000,000,000
- 요청은 정렬되어 있지 않습니다.

## 입출력 예

| requests | result |
|---|---|
| [[1, 2, 5], [2, 3, 6], [4, 2, 5], [6, 1, 4]] | 14 |
| [[0, 10, 100], [0, 5, 60], [5, 5, 60]] | 120 |
| [[3, 4, 9], [1, 3, 4], [2, 6, 8], [7, 2, 4]] | 13 |

## 입출력 예 설명
- 예 #1: 요청이 쓰는 시간은 차례로 [1, 3), [2, 5), [4, 6), [6, 7)입니다. [1, 3), [4, 6), [6, 7)을 받으면 5 + 5 + 4 = 14입니다.
- 예 #2: [0, 5)와 [5, 10)은 겹치지 않으므로 함께 받아 120을 얻습니다. 10시간짜리 요청 하나(100)보다 많습니다.
- 예 #3: 쓰는 시간은 [3, 7), [1, 4), [2, 8), [7, 9)입니다. [3, 7)과 [7, 9)를 받으면 9 + 4 = 13입니다.
