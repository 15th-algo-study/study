# 해설 — 압축 문서의 k번째 글자

## 접근
문서를 실제로 풀면 길이가 10^18을 넘을 수 있으므로 **길이만 계산하고, k번째 글자가 어느 조각에 있는지 따라 내려갑니다.**

1. **파싱**: 스택으로 압축 문자열을 트리로 바꿉니다. 노드는 "글자 하나" 또는 "x번 반복 블록(안쪽 노드 목록)"입니다. 블록을 닫을 때 `(안쪽 길이) × x`로 블록 길이를 계산합니다.
2. **내려가기**: 현재 노드 목록을 앞에서부터 보며 `k`가 그 노드 길이 이하인 노드를 찾습니다 (지나친 노드 길이는 `k`에서 뺍니다).
   - 글자 노드면 그 글자가 답입니다.
   - 반복 블록이면 같은 내용이 반복되므로 `k = (k - 1) % 안쪽길이 + 1`로 줄이고 안쪽 목록으로 내려갑니다.

## 주의할 점
- **길이 오버플로**: `1000000000[1000000000[...]]`처럼 곱하면 `long`도 넘칩니다. `k ≤ 10^18`이므로 길이가 10^18보다 크기만 하면 정확한 값은 필요 없습니다. 상한(예: 2×10^18)을 두고 곱셈 전에 `a > CAP / b`로 넘침을 확인하세요.
- 상한이 걸린 블록 안에서 `(k-1) % 안쪽길이`는, 안쪽 길이도 상한 이상이면 k가 그대로 유지되어 첫 번째 반복 안을 가리킵니다. 실제로도 k가 첫 반복 안에 있으므로 맞습니다.
- **깊은 중첩**: 괄호가 수만 겹이면 재귀 파서는 스택 오버플로가 날 수 있습니다. 명시적 스택으로 파싱하고, 내려가기도 반복문으로 합니다.
- 직접 문자열을 풀어 보는 방법은 메모리·시간 모두 불가능합니다.

## 복잡도
- 시간 O(|s|): 파싱 O(|s|), 내려가기는 각 노드 목록을 한 번씩만 훑습니다.
- 공간 O(|s|)
