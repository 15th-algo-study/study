# 해설 — 스프레드시트 정렬 되감기

## 핵심 관찰: 안정 정렬을 여러 번 = 다중 기준 정렬 한 번
안정 정렬을 차례로 적용하면, **마지막 명령**이 1순위 기준이 되고, 그 값이 같은 행들은 **직전 명령**의 순서를 따르며, … 이런 식으로 거슬러 올라갑니다. 끝까지 모든 기준이 같으면 처음 순서, 즉 원래 행 번호 순입니다.

그러므로 명령 `k`개를 실제로 `k`번 정렬할 필요 없이, **명령을 거꾸로 읽어 만든 다중 기준 비교자**로 한 번만 정렬하면 됩니다.

또 하나의 관찰: 같은 열이 여러 번 등장하면 **마지막 등장만 의미가 있습니다**. 뒤쪽 명령에서 그 열의 값이 같은 행들은, 앞쪽 명령(같은 열)에서도 값이 같아 순서가 바뀌지 않기 때문입니다. 따라서 유효한 기준은 열 수 `m ≤ 5`개 이하입니다.

## 알고리즘
1. 명령을 **뒤에서부터** 읽으며, 아직 나오지 않은 열이면 `(열, 방향)`을 기준 목록에 추가합니다 (최대 `m`개).
2. 행 번호 배열 `0 … n-1`을 "기준 목록 순서대로 비교 → 모두 같으면 번호 오름차순" 비교자로 정렬합니다.
3. 정렬된 번호 배열을 돌려줍니다.

## 주의할 점
- 명령마다 정렬을 다시 하면 10만 번 × O(n log n) 이라 시간 초과입니다. 기준을 모아 한 번만 정렬하세요.
- 값 범위가 ±10^9 이므로 `a - b` 비교는 넘칩니다. `Integer.compare`를 쓰고, `desc`는 인자 순서를 바꿉니다.
- 모든 기준이 같을 때 **원래 번호 순**이 되도록 마지막 비교를 꼭 넣으세요. `Arrays.sort(Object[])`가 안정 정렬이라 번호 배열을 순서대로 채웠다면 생략해도 같지만, 의도를 코드로 남기는 편이 안전합니다.
- 명령 문자열은 `"c asc"` 형식이 고정이므로 `split(" ")` 또는 `charAt`으로 간단히 나눌 수 있습니다.

## 복잡도
- 시간 O(k + n log n · m) (k = 명령 수), 공간 O(n)
