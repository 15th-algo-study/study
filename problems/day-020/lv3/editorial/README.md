# 해설 — 소풍 돗자리 넓이

## 핵심 관찰 1: 세로 띠 안에서는 덮인 모양이 변하지 않는다 (좌표 압축)
좌표가 10^9 까지라 격자를 칠할 수 없습니다. 하지만 덮인 영역의 모양은 **어떤 돗자리의 왼쪽 변이나 오른쪽 변을 지날 때만** 바뀝니다. 모든 `x`와 `x + w`를 모아 정렬하면 최대 `2n` 개의 경계가 생기고, 이웃한 두 경계 사이의 **세로 띠** 안에서는 어느 돗자리가 걸쳐 있는지가 일정합니다.

그러므로 띠마다 "걸쳐 있는 돗자리들의 `y` 구간 합집합 길이"를 구해 띠 너비를 곱하고 모두 더하면 됩니다.

## 핵심 관찰 2: 띠 안의 합집합 길이는 "구간 합치기"
한 띠에 걸친 돗자리들의 `[y, y + h)` 구간을 `y` 오름차순으로 보며 합칩니다 (제설 구간 문제와 같은 방법). 돗자리를 **미리 `y` 순으로 한 번 정렬**해 두고, 띠마다 그 순서로 훑으며 "이 띠에 걸치는가(`x ≤ 띠 왼쪽` 이고 `띠 오른쪽 ≤ x + w`)"만 확인하면 띠마다 정렬을 다시 할 필요가 없습니다.

## 알고리즘
1. `xs` = 모든 `x`, `x + w` 를 정렬한 배열. 이웃한 서로 다른 값 쌍 `(xs[i], xs[i+1])`이 하나의 띠.
2. 돗자리를 `y` 오름차순으로 정렬.
3. 각 띠에 대해 정렬된 돗자리를 순서대로 보며, 띠에 걸친 것만 골라 `[y, y+h)` 구간을 합치고 덮인 길이 `len`을 구한다.
4. `answer += len × (xs[i+1] − xs[i])`.

띠 최대 `2n − 1` 개 × 돗자리 `n` 개 = 약 5×10^7 번의 확인으로 충분합니다.

## 주의할 점
- 넓이는 최대 10^18 이므로 `long`이 필수입니다. `len × 너비`를 곱하기 전에 둘 다 `long`이어야 합니다.
- 경계가 **반열린 구간**(`x ≤ X < x + w`)이므로 꼭짓점·변만 닿는 돗자리는 겹치지 않습니다(예 #3). 띠에 걸치는지 판단할 때 `x ≤ left && right ≤ x + w` 처럼 띠 전체가 돗자리 안에 들어가는지를 봅니다.
- 같은 `x` 값이 여러 개면 너비 0인 띠가 생깁니다. 건너뛰거나 그대로 계산해도(0을 더함) 됩니다.
- 압축한 격자(최대 10,000 × 10,000 칸)에 돗자리마다 칸을 하나씩 칠하는 방법은 돗자리가 크면 칸 수가 수백억에 이르러 시간 초과입니다. 띠 단위로 묶어 처리하는 것이 핵심입니다.
- 압축 격자에 2차원 차분을 쓰는 풀이도 O(n + 격자 칸 수) = 약 10^8 로 시간은 통과할 수 있지만, `int` 격자 하나가 400MB 에 이르러 메모리가 빠듯하고 구현도 더 깁니다. 띠 방식은 추가 메모리가 O(n)뿐입니다.

## 복잡도
- 시간 O(n²) (띠 2n개 × 돗자리 n개), 공간 O(n)
