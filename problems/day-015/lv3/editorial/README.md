# 해설 — 겹치지 않는 목표 구간

## 접근
두 가지 관찰을 합칩니다.

**관찰 1 (그리디).** 겹치지 않는 구간을 최대한 많이 고르려면, 가능한 구간 중 **끝이 가장 빠른 것**을 고르고 그 뒤에서 다시 같은 선택을 반복하면 됩니다. 끝이 더 늦은 구간을 고르면 그 뒤에 남는 판이 줄어들 뿐 이득이 없습니다.

**관찰 2 (누적합 + 해시).** 끝 위치 `r`로 끝나며 합이 `k`인 묶음이 있는지는, 누적합 `P[r+1]`에 대해 `P[l] = P[r+1] - k`인 `l`이 있는지로 알 수 있습니다. 단, `l`은 **마지막으로 고른 묶음의 끝 이후**여야 합니다.

두 관찰을 합치면 한 번의 순회로 끝납니다.

1. `HashSet<Long> seen`에 누적합 `0`을 넣고 (`P[0]`), 누적합 `prefix = 0`으로 시작합니다.
2. 판을 하나씩 보며 `prefix += scores[i]`.
3. `seen`에 `prefix - k`가 있으면 → 여기서 끝나는 목표 묶음이 있고, 끝이 가장 빠른 것이므로 고릅니다. 답을 1 늘리고 **`seen`을 비운 뒤** `prefix`만 넣습니다 (다음 묶음은 `i + 1`번 판부터 시작해야 하므로 `P[i+1]`만 유효한 시작점입니다).
4. 없으면 `seen`에 `prefix`를 넣습니다.

3번에서 "있는지 확인"을 "넣기" **전에** 해야 길이 0인 묶음(`k = 0`일 때 `prefix - 0 = prefix`)이 세어지지 않습니다.

## 주의할 점
- 가능한 묶음을 모두 찾아 두고 고르는 O(n²)은 30만 개에서 4.5×10^10 번이라 시간 초과입니다. 특히 목표 묶음이 거의 없는 입력에서 끝까지 훑게 됩니다.
- 음수 점수가 있어서 투 포인터는 쓸 수 없습니다.
- 누적합은 최대 3×10^11이므로 `long`입니다.
- 묶음을 고른 뒤 `seen`을 비우지 않으면 이전 묶음과 겹치는 시작점을 쓰게 됩니다. 예 #3에서 `[5, -5]`를 고른 뒤 `[-5, 5]`도 세어 2가 나옵니다.
- `clear()`는 집합 크기에 비례하지만, 각 원소는 한 번 들어가 한 번 지워지므로 전체 비용은 O(n)입니다.

## 복잡도
- 시간 O(n), 공간 O(n)
