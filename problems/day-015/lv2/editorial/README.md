# 해설 — 의심스러운 중복 결제

## 접근
"같은 카드 + 같은 가게"가 하나의 단위이므로 두 문자열을 **합쳐서 하나의 키**로 만듭니다. 키 → 마지막 결제 시각을 `HashMap<String, Integer>`에 들고 가며

1. 키가 맵에 있고 `times[i] - last ≤ limit`이면 답을 1 늘립니다.
2. 키의 값을 `times[i]`로 갱신합니다 (의심 여부와 관계없이 항상).

기록이 시각 순이므로 "가장 최근 결제"는 맵에 마지막으로 넣은 값입니다.

## 주의할 점
- 키를 `cards[i] + shops[i]`로 그냥 이어 붙이면 `"ab" + "c"`와 `"a" + "bc"`가 같은 키가 됩니다 (예 #3). 이름에 쓰이지 않는 문자(예: `#`, `|`)를 사이에 넣으세요.
- 직전 결제가 중복 의심이어도 그 시각으로 갱신해야 합니다 (예 #2). 갱신을 건너뛰면 2번 결제가 0번 기준으로 2초 차이가 되어 틀립니다.
- 결제마다 앞쪽 기록을 거슬러 올라가며 같은 카드·가게를 찾으면, 조합이 많고 시각이 몰려 있을 때 O(n²)으로 시간 초과입니다.
- `times[i] - last`는 최대 10^9라 `int`로 충분합니다.

## 복잡도
- 시간 O(n · L) (L = 이름 길이), 공간 O(카드·가게 조합 수)
