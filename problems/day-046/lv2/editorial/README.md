# 해설 — 온천 가족탕 예약

## 접근
구간 스케줄링의 기본형입니다. **끝나는 시각이 가장 이른 예약부터** 받고, 그 끝 시각 이후에 시작하는 예약 중 다시 가장 일찍 끝나는 것을 받는 일을 반복합니다.

왜 맞는지(교환 논법): 어떤 최적해를 잡고 그 안에서 가장 먼저 끝나는 예약을 `x`라 하면, 전체에서 가장 먼저 끝나는 예약 `g`는 `g`의 끝 ≤ `x`의 끝이므로 `x`를 `g`로 바꿔도 나머지와 겹치지 않습니다. 따라서 `g`를 포함하는 최적해가 있고, `g` 이후에 시작하는 예약들에 같은 논리를 반복하면 그리디의 선택이 최적해와 같은 개수가 됩니다.

구현: `end = start + duration`을 계산해 `end` 오름차순으로 정렬한 뒤, 마지막으로 받은 예약의 끝 `last`보다 `start`가 크거나 같은 예약을 만날 때마다 받습니다.

## 주의할 점
- `start + duration`은 최대 2×10^9라 `int`를 넘칩니다. `long`으로 계산하세요.
- "가장 짧은 것부터"(예 #2), "가장 먼저 시작하는 것부터"(예 #3)는 그럴듯하지만 틀린 그리디입니다.
- 끝 시각과 다음 시작 시각이 같으면 받을 수 있으므로 비교는 `start >= last`입니다.
- 정렬 뒤 각 예약마다 "앞에서 받을 수 있는 최대 개수"를 모두 훑어 구하는 O(n²) DP는 20만 개에서 시간 초과입니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
