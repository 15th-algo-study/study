# 해설 — 서커스 인간 탑

## 접근
**`weight + strength`가 작은 단원일수록 위에** 세우면 됩니다. 그 순서로 세운 뒤 위에서부터 몸무게를 누적하며 각 단원의 위험도를 계산하고 최댓값을 구합니다.

### 왜 맞는가 (교환 논법)
위아래로 **이웃한** 두 단원 `a`(위), `b`(아래)만 서로 바꿔 봅니다. 두 사람 위에 있는 몸무게 합을 `W`라 하면, 둘 이외 단원의 위험도는 바뀌지 않습니다(둘 위의 단원은 영향이 없고, 둘 아래 단원은 위의 몸무게 합이 그대로입니다).

- `a`가 위일 때 두 사람의 위험도: `W − s_a`, `W + w_a − s_b`
- `b`가 위일 때: `W − s_b`, `W + w_b − s_a`

`W + w_a − s_b > W − s_a`이고 `W + w_b − s_a > W − s_b`이므로 두 경우의 최댓값은 각각 `W + w_a − s_b`, `W + w_b − s_a`입니다. 전자가 후자보다 작거나 같을 조건은 `w_a − s_b ≤ w_b − s_a`, 즉 **`w_a + s_a ≤ w_b + s_b`** 입니다.

따라서 어떤 순서든 `w + s`가 큰 단원이 작은 단원 바로 위에 있으면 둘을 바꿔도 공연 위험도가 커지지 않습니다. 이 교환을 반복하면(버블 정렬처럼) 어떤 최적해도 `w + s` 오름차순으로 바꿀 수 있으므로, 오름차순 배치가 최적입니다. `w + s`가 같은 단원끼리는 어느 순서든 같습니다.

### 가짜 그리디
- "힘이 센 사람을 아래에"(`strength` 오름차순으로 위에서부터): 예 #1에서 7이 나와 틀립니다.
- "가벼운 사람을 위에"(`weight` 오름차순): 예 #1에서 역시 7이 나옵니다. `[4, 1, 9, 7] / [1, 2, 0, 8]`처럼 둘 다 틀리는 입력도 있습니다(정답 6).

## 주의할 점
- 누적 몸무게는 최대 2×10^14라 `long`이 필요하고, `w + s`도 최대 2×10^9라 `long`으로 비교해야 합니다.
- 정렬 키로 `Integer[]` 인덱스 배열을 정렬하거나 `long` 하나에 `(w+s, 인덱스)`를 묶어 정렬합니다. 순서 자체는 필요 없고 `(w+s, w, s)` 묶음만 정렬하면 됩니다.
- 최댓값의 초깃값은 `Long.MIN_VALUE`로 두세요. 답이 음수일 수 있습니다.
- 모든 순서를 시도하는 완전탐색은 `n!`이라 `n = 12`만 돼도 불가능합니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
