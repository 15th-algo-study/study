# 해설 — 향신료 배합 레시피 수

## 접근
통마다 "넣는다/안 넣는다"를 재귀로 정하는 완전탐색은 2^40 ≈ 1.1×10^12 가지라 시간 초과입니다. 무게가 10^9까지라 "총량별 방법 수" 표(DP)도 만들 수 없습니다.

**관찰: 통을 반으로 나누면 각 절반은 2^20 ≈ 10^6 가지뿐입니다.** (중간에서 만나기, meet in the middle)

1. 앞 절반 통들로 만들 수 있는 모든 부분집합의 총량을 배열 `A`에, 뒤 절반의 총량을 배열 `B`에 넣습니다 (빈 집합의 0도 포함). 각각 재귀나 반복으로 2^20개를 열거합니다.
2. 전체 레시피는 "앞 절반에서 하나, 뒤 절반에서 하나"를 짝지은 것이므로, 답은 `lo ≤ a + b ≤ hi`인 쌍 `(a, b)`의 수입니다.
3. `A`, `B`를 정렬하면 "`a + b ≤ T`인 쌍의 수"는 **투 포인터**로 O(|A| + |B|)에 셀 수 있습니다: `A`를 작은 것부터 보며 `B`의 포인터를 큰 쪽에서 왼쪽으로만 움직입니다. 답은 `count(hi) − count(lo − 1)`입니다.
4. 빈 집합끼리 짝지은 총량 0이 `[lo, hi]`에 들어가면 하나 빼야 하지만, `lo ≥ 1`이므로 이 문제에서는 생기지 않습니다 (모범 풀이는 안전하게 처리합니다).

## 주의할 점
- 총량은 최대 4×10^10 이라 부분집합 합, `lo`, `hi` 비교 모두 `long`입니다.
- 부분집합 합 열거는 "지금까지의 합 목록에 새 통의 무게를 더한 복사본을 이어 붙이기"로 반복문으로도 만들 수 있습니다. 재귀로 만들면 깊이 20이라 안전합니다.
- 2^20개의 `long` 배열 두 개와 정렬은 수백 ms면 끝납니다. `List<Long>`에 박싱해서 담으면 몇 배 느려지므로 `long[]`을 씁니다.
- 쌍의 수를 이분 탐색(`B`에서 `hi − a` 이하인 개수)으로 세면 O(2^20 × 20)으로 조금 더 느리지만 역시 통과합니다.
- 정렬한 무게로 "남은 무게를 다 더해도 `lo`에 못 미치면 중단" 같은 가지치기를 넣은 완전탐색은 구간이 넓으면 전혀 잘리지 않아 시간 초과입니다. `large_01`은 모든 레시피가 조건을 만족하는 입력입니다.

## 복잡도
- 시간 O(2^(n/2) × n/2) (정렬이 지배), 공간 O(2^(n/2))
