# 해설 — 입고 횟수 질의

## 접근
질의마다 구간을 훑으면 O(n·q) = 4×10^10으로 시간 초과입니다. 품목 번호가 10억까지라 품목별 누적합 배열도 만들 수 없습니다. 관찰은 두 가지입니다.

1. 질의는 `x` 하나만 묻습니다. 그러므로 **품목별로 들어온 위치 목록**만 있으면 됩니다. `HashMap<Integer, List<Integer>>`에 품목 → 위치 목록을 만들면, 위치는 자연히 오름차순입니다. 전체 목록 길이의 합은 `n`입니다.
2. 오름차순 목록에서 "`[l, r]` 안에 있는 위치의 개수"는 **이분 탐색** 두 번입니다: (`r` 이하인 원소 수) - (`l` 미만인 원소 수). 즉 `upperBound(r) - lowerBound(l)`.

`x`가 맵에 없으면 답은 0입니다.

### 다른 방법 — 오프라인 누적 횟수
`[l, r]`의 답은 `(0~r에서 x의 개수) - (0~l-1에서 x의 개수)`입니다. 질의를 끝 위치별로 모아 둔 뒤, 기록을 앞에서부터 보며 `HashMap`에 품목별 개수를 쌓고, 위치 `p`에 걸린 질의들에 그때의 개수를 더하거나 빼면 이분 탐색 없이 O(n + q)에 풀립니다.

## 주의할 점
- `List<Integer>`에서 `Collections.binarySearch`는 중복이 있을 때 어느 위치를 돌려줄지 보장하지 않습니다. 직접 `lowerBound`를 쓰거나, 위치를 `int[]`로 바꿔 두세요.
- 한 품목이 20만 번 들어오는 경우(목록 하나가 전체)도 이분 탐색이면 문제없습니다.
- 답의 개수는 `queries.length`이므로 `int[]`를 미리 만들어 채웁니다.

## 복잡도
- 시간 O(n + q log n), 공간 O(n + q)
