# 해설 — 초콜릿 바 쪼개기

## 접근
규칙을 그대로 옮긴 재귀는 다음과 같습니다.

> `pieces(x)` = `x ≤ limit ? 1 : pieces(⌊x/2⌋) + pieces(⌈x/2⌉)`

맞는 식이지만 호출 횟수가 **조각 개수만큼**(최대 10^18) 늘어나 시간 초과입니다. 메모 없는 재귀의 전형적인 한계입니다.

**관찰: 같은 깊이의 조각은 길이가 많아야 두 가지이고, 그 둘은 1 차이입니다.** 처음 길이 `L` 하나에서 시작해 반으로 쪼개면 `⌊L/2⌋`과 `⌈L/2⌉`뿐이고, 길이 `m`과 `m+1`을 각각 쪼개도 나오는 길이는 `⌊m/2⌋`, `⌈m/2⌉`, `⌊(m+1)/2⌋`, `⌈(m+1)/2⌉`의 두 종류뿐입니다 (`m`이 짝수면 `m/2`, `m/2+1`, 홀수면 `(m−1)/2`, `(m+1)/2`).

따라서 "길이 `lo`가 `cLo`개, 길이 `lo+1`이 `cHi`개"만 들고 한 단계씩 내려가면 됩니다.

1. `lo + 1 ≤ limit`이면 모두 끝: `cLo + cHi`를 더하고 종료.
2. `lo ≤ limit < lo + 1`이면 길이 `lo` 조각은 끝: `cLo`를 답에 더하고, 길이 `lo + 1`만 다음 단계로. (`lo + 1` 조각이 하나도 없으면 여기서 종료합니다. 이 검사를 빠뜨리면 `limit = 1`에서 개수 0인 조각을 영원히 쪼개는 무한 루프가 됩니다.)
3. 남은 조각들을 쪼개 새 `(lo, cLo, cHi)`를 만듭니다.
   - `lo`가 짝수: 새 `lo' = lo/2`, `cLo' = 2·cLo + cHi`, `cHi' = cHi`
   - `lo`가 홀수: 새 `lo' = (lo−1)/2`, `cLo' = cLo`, `cHi' = cLo + 2·cHi`

길이가 매 단계 절반이 되므로 단계 수는 많아야 60입니다.

## 주의할 점
- 조각 수가 최대 10^18이라 `cLo`, `cHi`, 답 모두 `long`입니다. `2·cLo + cHi`도 전체 조각 수(≤ L)를 넘지 않으므로 넘치지 않습니다.
- 재귀 + `HashMap` 메모로도 풀립니다. 깊이마다 상태가 2개뿐이라 질문당 120개 정도의 상태만 방문하지만, 20만 질문에 박싱 비용이 쌓여 위 반복문보다 몇 배 느립니다. 제한 안에 들려면 메모 쪽은 세심하게 짜야 합니다.
- `limit ≥ length`인 질문은 바로 1입니다. 반복문의 1번 조건이 처리해 주지만, 따로 처리해도 좋습니다.

## 복잡도
- 시간 O(q × log L) (q = 질문 수), 공간 O(q) (결과)
