# 해설 — 중고 장터의 최저가

## 접근
최저가 질의는 **최소 힙**이 답하지만, 자바의 `PriorityQueue`는 "맨 위가 아닌 원소 삭제"가 O(n)입니다(`remove(Object)`는 선형 탐색). 그래서 **지연 삭제(lazy deletion)** 를 씁니다.

- 힙에는 `(가격, 상품 번호)`를 넣습니다.
- 상품이 내려가면 힙은 건드리지 않고 `removed[번호] = true`만 표시합니다.
- 최저가를 물을 때 힙의 맨 위가 이미 내려간 상품이면(`removed`가 참) 그제야 `poll`로 버립니다. 맨 위가 살아 있는 상품이 될 때까지 반복한 뒤 `peek`합니다.

각 상품은 힙에 한 번 들어가고 한 번만 나가므로 전체 `poll` 횟수는 등록 수를 넘지 않습니다.

## 주의할 점
- 질의마다 살아 있는 상품을 모두 훑어 최솟값을 찾으면 O(n²)입니다. 상품 10만 개가 올라온 뒤 질의 10만 번이면 10^10이라 시간 초과입니다.
- `PriorityQueue.remove(Object)`로 직접 지우는 것도 O(n)이라 같은 이유로 느립니다.
- 내리기 요청의 번호는 아직 등록되지 않았거나(`v > 등록 수`) 10^9처럼 아주 클 수 있습니다. `removed` 배열을 `v`로 바로 인덱싱하기 전에 범위를 확인하세요. 배열 크기는 `events`의 길이 + 1이면 충분합니다(등록 수 ≤ 기록 수).
- 같은 가격의 상품이 여럿이어도 번호가 달라 별개로 다뤄집니다. `(가격, 번호)` 비교자에서 번호까지 비교할 필요는 없지만, 넣어 두면 순서가 결정적이 됩니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
