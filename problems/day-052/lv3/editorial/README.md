# 해설 — 무대 조명의 밝기 면적

## 접근
밝기가 바뀔 수 있는 지점은 어떤 조명의 **시작점이나 끝점**뿐입니다. 그 사이 구간에서는 비추는 조명 집합이 같으므로 밝기도 같습니다. 그래서 좌표를 왼쪽에서 오른쪽으로 **스위핑**하면서 "지금 켜진 조명 중 최대 밝기"만 알면 됩니다.

1. 조명을 시작점 `s` 기준으로 정렬하고, 모든 시작점·끝점을 모아 정렬합니다(이벤트 좌표).
2. 이벤트 좌표 `x`를 차례로 보면서
   - 끝점이 `x` 이하인 조명을 꺼야 하는데, 최대 힙에서 맨 위가 아닌 원소는 바로 지울 수 없으므로 **지연 삭제**를 씁니다: 힙에는 `(밝기, 끝점)`을 넣어 두고, 맨 위의 끝점이 `x` 이하이면 `poll`로 버리기를 반복합니다. 맨 위가 아닌 꺼진 조명은 밝기가 더 작으니 답에 영향이 없고, 나중에 맨 위로 올라오면 그때 버려집니다.
   - 시작점이 `x`인 조명을 힙에 넣습니다.
   - 힙 맨 위의 밝기(비었으면 0)가 `[x, 다음 이벤트 좌표)` 구간의 밝기입니다. `(다음 좌표 − x) × 밝기`를 더합니다.

## 주의할 점
- 좌표 압축 후 조각마다 모든 조명을 훑으면 O(n²)이라 20만 개에서 시간 초과입니다. 조명을 밝기 내림차순으로 정렬해 "아직 안 칠한 구간"을 색칠하는 방법도 O(n log n)으로 가능하지만 구현이 더 복잡합니다.
- `PriorityQueue.remove(Object)`로 끝난 조명을 지우면 O(n)이라 역시 시간 초과입니다. 지연 삭제가 핵심입니다.
- 끝점은 `s + len`으로 최대 2×10^9라 `int`를 넘습니다. 좌표와 면적 계산은 모두 `long`으로 하세요. 면적은 최대 2×10^9 × 10^9 = 2×10^18로 `long` 안입니다.
- 시작점과 끝점이 같은 좌표에 있으면 끝나는 조명을 먼저 빼고 시작하는 조명을 넣습니다. 구간은 끝점을 포함하지 않으므로 `끝점 ≤ x`인 조명은 이미 꺼진 것입니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
