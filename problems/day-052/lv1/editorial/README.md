# 해설 — 우주 정거장 수리 요청

## 접근
"가장 긴급한 것, 같으면 먼저 온 것"을 꺼내는 자료구조가 바로 **우선순위 큐**입니다. 요청을 `(긴급도, 번호)` 쌍으로 넣고 비교자를 다음처럼 둡니다.

1. 긴급도가 **큰** 쪽이 먼저 → `Integer.compare(b[0], a[0])`
2. 긴급도가 같으면 번호가 **작은** 쪽이 먼저 → `Integer.compare(a[1], b[1])`

`'A'`면 `offer`, `'P'`면 비어 있지 않을 때 `poll`해서 번호를 기록합니다.

## 주의할 점
- `'P'`마다 리스트를 훑어 최댓값을 찾으면 O(n²)입니다. 요청 10만 개가 쌓인 뒤 `P` 10만 번이면 10^10번 비교라 시간 초과입니다. 힙은 연산마다 O(log n)입니다.
- 비교자에서 `b[0] - a[0]`처럼 뺄셈을 쓰면 값이 크면 오버플로할 수 있습니다. 여기서는 긴급도가 10^6 이하라 괜찮지만 `Integer.compare`를 쓰는 습관이 안전합니다. `Comparator.comparingInt(...)`와 `thenComparingInt(...)`로 써도 좋습니다.
- 답의 개수는 `'P'`의 개수와 같으므로 미리 세어 배열을 만들거나 `List`에 모았다가 바꿉니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
