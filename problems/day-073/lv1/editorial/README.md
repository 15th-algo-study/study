# 해설 — 조각보의 대칭 구간

## 접근
구간 `[l, r]`이 대칭인지 매번 처음부터 확인하면 구간 수 O(n²) × 확인 O(n) = O(n³)입니다. n = 10,000이면 약 10^11번이라 시간 초과입니다.

**관찰**: 구간 `[l, r]`이 대칭이려면 양 끝 글자가 같고(`s[l] == s[r]`) **안쪽 구간 `[l+1, r-1]`이 대칭**이어야 합니다. 즉 긴 구간의 답은 짧은 구간의 답으로 정해집니다(구간 DP).

이 관찰을 그대로 쓰는 가장 간단한 방법이 **가운데에서 넓혀 가기**입니다.
1. 가운데를 정합니다. 길이가 홀수인 구간은 가운데가 글자 하나(`l = r = c`), 짝수인 구간은 가운데가 두 글자 사이(`l = c, r = c + 1`)입니다. 가운데 후보는 총 2n − 1개입니다.
2. `s[l] == s[r]`인 동안 `l--`, `r++`로 넓히며, 넓힐 때마다 대칭 구간 하나를 셉니다.
3. 양 끝이 달라지는 순간 멈춥니다. 바깥 구간도 모두 대칭이 아니기 때문입니다(위 관찰).

각 넓히기 단계가 대칭 구간 하나에 대응하므로, 전체 작업량은 "대칭 구간 수 + 가운데 수" = O(n²) 이하입니다.

표로 풀고 싶다면 `pal[l][r] = (s[l] == s[r]) && (r - l < 2 || pal[l+1][r-1])`을 길이가 짧은 구간부터 채우면 됩니다. 결과는 같지만 n × n 표(10^8칸)가 필요합니다.

## 주의할 점
- 짝수 길이 대칭 구간(`aa`, `abba`)을 빠뜨리기 쉽습니다. 가운데를 글자 위와 글자 사이 두 종류 모두 시도하세요.
- 최대 개수는 모든 글자가 같을 때 n(n+1)/2 = 50,005,000으로 `int` 범위 안입니다.
- 부분 문자열을 `substring`으로 만들어 뒤집어 비교하면 O(n³)에 문자열 생성 비용까지 더해져 훨씬 느립니다.

## 복잡도
- 시간 O(n²) (최악: 모든 글자가 같을 때), 공간 O(n)
