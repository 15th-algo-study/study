# 해설 — 코스 요리 고르기

## 접근
코너 하나를 "물건 한 묶음"으로 보면 **그룹 배낭** 문제입니다. 각 묶음에서 0개 또는 1개를 고릅니다.

- `best[b]` = 지금까지 처리한 코너들에서 요리를 골라 가격 합이 `b`원 이하일 때 만족도 합의 최댓값
- 처음에는 모두 0

코너를 하나씩 처리합니다. 코너를 처리하기 **직전의 표를 복사**해 `before`로 두고, 그 코너의 요리 `(price, joy)`마다

`best[b] = max(best[b], before[b - price] + joy)` (`b ≥ price`)

로 갱신합니다. 오른쪽 항이 항상 `before`(이 코너에서 아직 아무것도 안 고른 상태)를 보므로, 같은 코너에서 두 요리를 고르는 경우가 생기지 않습니다. 요리를 하나도 안 고르는 경우는 `best[b]`가 원래 값을 유지하는 것으로 처리됩니다.

코너별로 묶기 위해 코너 번호(1~1,000)를 인덱스로 하는 리스트 배열에 요리를 나눠 담거나, `menus`를 코너 번호로 정렬합니다.

## 주의할 점
- 일반 0/1 배낭처럼 한 표를 요리마다 갱신하면, 같은 코너의 요리 두 개를 함께 고르는 경우가 섞여 틀립니다(예 #1에서 1번 코너 두 요리 + 2번 코너 (2원, 3) → 16).
- 코너 안에서는 요리 순서와 `b`의 방향이 상관없습니다. 읽는 쪽이 모두 `before`이기 때문입니다.
- 모든 코스 조합을 시도하면 (코너별 선택지 수)의 곱이라 지수적으로 많습니다.

## 복잡도
- 시간 O(코너 수 × budget + 요리 수 × budget), 공간 O(budget)
