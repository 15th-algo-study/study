# 해설 — 가장 붐비는 시간

## 접근
회의마다 차지하는 초를 하나씩 +1 하면 회의 하나에 최대 86,400번, 전체 1.7×10^10번이라 시간 초과입니다. **차분 배열**을 씁니다.

1. `"HH:MM:SS"`를 초로 바꿉니다: `HH*3600 + MM*60 + SS`.
2. 회의가 차지하는 구간 `[start, start + D)`에 대해 `diff[start]++`, `diff[end]--`.
3. 구간이 86,400을 넘으면 두 조각 `[start, 86400)`과 `[0, end - 86400)`으로 나눠 기록합니다. `D ≤ 86400`이라 두 조각을 넘지 않습니다.
4. `diff`를 앞에서부터 누적하면 각 초의 동시 회의 수입니다. 최댓값과 그 횟수를 셉니다.

## 주의할 점
- 끝 시각은 **포함하지 않습니다** (`09:00:00 3600`은 `09:59:59`까지). 구간을 `[start, end)`로 두면 경계 처리가 깔끔합니다.
- `D = 86400`이고 `start > 0`이면 정확히 하루를 감싸 두 조각이 됩니다. 예 #3에서 확인하세요.
- 문자열 파싱은 `split(":")`, `split(" ")`도 되지만 형식이 고정이라 `substring`이 빠릅니다.

## 복잡도
- 시간 O(n + 86400), 공간 O(86400)
