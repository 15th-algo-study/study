# 해설 — 비상구 안내 표지판

## 접근
각 정점에서 나가는 간선이 정확히 하나인 **함수 그래프**입니다. 어떤 방에서 출발하든 경로는 "꼬리(사이클 밖 구간) → 사이클" 모양이고, 지나간 서로 다른 방의 수는 **꼬리 길이 + 사이클 길이**입니다.

출발 방마다 직접 따라가면 한 번에 최대 n 번 이동이라 O(q × n) = 6×10^11 로 시간 초과입니다. **관찰**: 같은 방에 도착하면 그 뒤의 경로는 같으므로, `count[v]` = "v 에서 출발했을 때의 답"은 `count[v] = count[next[v]] + 1` (v 가 사이클 밖일 때)로 재사용할 수 있습니다. 모든 방의 `count`를 **한 번에 전부** 구해 두고 질문에는 O(1)로 답합니다.

반복문으로 구현하는 방법:
1. 아직 처리되지 않은 방 `s`에서 출발해 `next`를 따라가며 지나간 방을 **스택(배열)** 에 쌓고, 각 방에 "지금 탐색 중" 표시(`state = 1`)를 합니다.
2. 멈추는 조건은 둘 중 하나입니다.
   - 이미 답이 정해진 방(`state = 2`)을 만남 → 스택을 거꾸로 꺼내며 `count[v] = count[next[v]] + 1`.
   - "지금 탐색 중"인 방을 다시 만남 → 그 방부터 스택 꼭대기까지가 **사이클**입니다. 사이클의 방 수 `L`을 세어 그 방들의 답을 모두 `L`로 정한 뒤, 사이클 아래의 나머지 스택은 위와 같이 `+1` 씩 채웁니다.
3. 처리한 방은 `state = 2`로 바꿉니다. 각 방은 한 번씩만 스택에 들어가므로 전체 O(n)입니다.

## 주의할 점
- **재귀 금지.** `count(v) = count(next[v]) + 1`을 재귀 함수로 쓰면 방이 한 줄로 300만 개 이어진 입력에서 재귀 깊이가 300만이 되어 StackOverflowError 가 납니다. large 에 이런 입력이 들어 있습니다. 반드시 반복문과 배열 스택으로 작성하세요.
- "지금 탐색 중"과 "완료"를 구분하는 **세 가지 상태**가 핵심입니다. `boolean visited` 하나로는 "사이클로 되돌아왔는지"와 "이미 답이 있는 방에 닿았는지"를 구별할 수 없습니다.
- 사이클에서 되돌아온 지점을 찾을 때 스택을 처음부터 훑으면 O(n²)이 될 수 있습니다. 각 방의 스택 위치를 배열에 기록해 두면(`pos[v]`) 사이클 길이를 O(1)에 구할 수 있습니다.
- `next[i] = i`는 길이 1인 사이클입니다. 따로 처리하지 않아도 위 규칙에 자연스럽게 들어갑니다.

## 복잡도
- 시간 O(n + q), 공간 O(n)
