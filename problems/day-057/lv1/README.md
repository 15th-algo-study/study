# [lv1] 공저자 찾기

연구자 `n`명에게 0번부터 `n-1`번까지 번호를 붙였습니다. 논문 공저 기록이 2차원 배열 `papers`로 주어집니다. `papers[i] = [a, b]`는 `a`번과 `b`번 연구자가 함께 논문을 쓴 적이 있다는 뜻입니다. 같은 두 사람이 여러 편을 함께 썼으면 같은 쌍이 여러 번 나올 수 있고, 입력 오류로 `a = b`인 기록이 섞여 있을 수 있습니다. 같은 쌍은 한 번만, `a = b`인 기록은 무시합니다.

질문 목록 `queries`가 주어집니다. `queries[i] = [v, k]`는 "`v`번 연구자의 공저자(함께 쓴 적이 있는 서로 다른 연구자)를 번호 오름차순으로 나열했을 때 `k`번째(1번부터 셈) 연구자의 번호"를 묻습니다. 공저자가 `k`명보다 적으면 답은 -1입니다.

각 질문의 답을 순서대로 담은 배열을 return 하도록 `solution` 함수를 완성해 주세요.

## 제한사항
- 1 ≤ `n` ≤ 200,000
- 0 ≤ `papers`의 길이 ≤ 200,000
- 1 ≤ `queries`의 길이 ≤ 200,000
- 0 ≤ `a`, `b`, `v` < `n`
- 1 ≤ `k` ≤ 200,000

## 입출력 예

| n | papers | queries | result |
|---|---|---|---|
| 5 | [[0, 3], [0, 1], [2, 0], [1, 2]] | [[0, 1], [0, 3], [0, 4], [1, 2], [4, 1]] | [1, 3, -1, 2, -1] |
| 3 | [[1, 2], [2, 1], [1, 1]] | [[1, 1], [1, 2], [2, 1]] | [2, -1, 1] |

## 입출력 예 설명
- 예 #1: 0번의 공저자는 {1, 2, 3}입니다. 1번째는 1, 3번째는 3, 4번째는 없으므로 -1입니다. 1번의 공저자는 {0, 2}이므로 2번째는 2입니다. 4번은 공저자가 없어 -1입니다.
- 예 #2: [1, 2]와 [2, 1]은 같은 쌍이고 [1, 1]은 무시하므로 1번의 공저자는 {2}뿐입니다.
