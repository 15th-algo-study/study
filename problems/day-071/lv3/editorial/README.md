# 해설 — 쟁반 포개기

## 접근
**1. 회전을 없앤다.** 각 쟁반을 `(짧은 변 s, 긴 변 l)`로 바꿔 씁니다. X를 Y 안에 넣을 수 있는 경우는 정확히 `sX < sY`이고 `lX < lY`일 때입니다.
- 이 조건이면 짧은 변끼리, 긴 변끼리 맞춰 넣으면 들어갑니다.
- 반대로 어떤 방향으로든 X가 들어간다면, 맞닿는 변끼리 `x1 < y1`, `x2 < y2`입니다. 그러면 `min(x1, x2) < min(y1, y2)`이고 `max(x1, x2) < max(y1, y2)`이므로 역시 `sX < sY`, `lX < lY`가 성립합니다.

**2. 한 변으로 정렬하고 다른 변으로 LIS.** 쟁반을 짧은 변 오름차순으로 정렬하면, 포갠 묶음은 정렬 순서에서 **긴 변이 엄격히 증가하는 부분 수열**이 됩니다. 단, 짧은 변이 같은 쟁반끼리는 포갤 수 없는데, 긴 변만 보면 증가할 수 있다는 함정이 있습니다.

→ **짧은 변이 같으면 긴 변 내림차순**으로 정렬합니다. 그러면 짧은 변이 같은 쟁반들의 긴 변은 내려가는 순서라, 엄격 증가 부분 수열에 둘 이상 함께 들어갈 수 없습니다.

**3. 엄격 증가 부분 수열(LIS)을 O(n log n)으로.** `tails[len]` = 길이 `len + 1`인 증가 부분 수열의 마지막 값 중 가장 작은 값. 새 값 `x`마다 `tails`에서 **`x` 이상인 첫 위치**(lower bound)를 찾아 `x`로 바꾸고, 없으면 뒤에 붙입니다. `tails`의 길이가 답입니다. `tails`는 항상 오름차순이라 이분 탐색이 됩니다.

## 주의할 점
- 정렬 기준 두 가지가 모두 중요합니다. 같은 짧은 변을 긴 변 **오름차순**으로 두면 `[2,3]`, `[2,4]`, `[2,5]`를 3개로 잘못 셉니다.
- "엄격히 작아야" 하므로 lower bound(이상인 첫 위치)를 씁니다. upper bound(초과인 첫 위치)를 쓰면 긴 변이 같은 쟁반을 이어 붙여 버립니다(예: `[1,5]`, `[2,5]`, `[3,5]` → 답 1).
- 모든 쌍을 비교하는 O(n²) DP는 n = 200,000에서 약 2×10^10번 비교라 시간 초과입니다.
- 길이는 10^9 이하라 `int` 비교로 충분합니다. 정렬 비교자에서 뺄셈(`a - b`) 대신 `Integer.compare`를 쓰세요.

## 복잡도
- 시간 O(n log n), 공간 O(n)
