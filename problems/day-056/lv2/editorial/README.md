# 해설 — 동굴 탐사 일지

## 접근
일지의 연속한 두 방이 간선입니다. 간선 목록이 "쌍의 배열"이 아니라 "경로"로 주어졌을 뿐, 결국 **무방향 그래프의 연결 요소 크기**를 구하는 문제입니다.

1. **인접 리스트 만들기.** 간선 수가 최대 200만이라 `ArrayList<Integer>` 200만 개는 느리고 메모리도 큽니다. 간선을 두 번 훑는 **배열 기반 인접 리스트**(CSR)를 씁니다.
   - 1차: 각 정점의 차수 `deg[v]`를 셉니다 (간선 하나에 양 끝 각각 +1).
   - 누적합으로 `start[v]` (정점 v 의 이웃이 시작하는 위치)를 만듭니다.
   - 2차: `to[pos[u]++] = v`, `to[pos[v]++] = u` 로 채웁니다.
   - 정점 v 의 이웃은 `to[start[v] .. start[v+1])` 입니다.
2. **연결 요소 탐색.** 방문하지 않은 정점마다 BFS/DFS 로 같은 요소를 모두 방문하며 개수를 셉니다.
3. 크기 목록을 정렬해 뒤집어 return 합니다.

## 주의할 점
- **재귀 DFS 는 위험합니다.** large 에는 방 180만 개가 한 줄로 이어진 일지가 있습니다. 재귀 깊이가 180만이 되어 스택을 크게 잡은 환경에서도 StackOverflowError 가 납니다. 큐를 쓰는 BFS 또는 `int[]` 스택을 쓰는 반복문 DFS 로 작성하세요.
- 같은 방이 연달아 적힌 경우(자기 자신으로 가는 간선)와 중복 간선은 방문 표시 덕분에 결과에 영향이 없습니다. 다만 차수를 셀 때 포함되므로 배열 크기는 "간선 수 × 2"로 잡아야 합니다.
- 결과 길이는 동굴계 수이며, 일지에 없는 방 각각이 크기 1인 요소입니다. 전체 정점을 빠짐없이 순회해야 빠뜨리지 않습니다.
- 크기 배열 정렬은 `Arrays.sort` 뒤 뒤집기, 또는 크기별 개수를 세는 카운팅 정렬 둘 다 괜찮습니다.

## 복잡도
- 시간 O(n + L + k log k) (L = 일지 길이 합, k = 동굴계 수), 공간 O(n + L)
