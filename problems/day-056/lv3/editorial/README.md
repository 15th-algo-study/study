# 해설 — 정글 캠프와 밧줄 다리

## 접근
계획마다 다리를 추가하고 BFS 를 돌리면 계획 하나에 O(n + m)이라 전체 O(q × (n + m)) ≈ 8×10^10 으로 시간 초과입니다. **관찰**: 다리를 하나 놓았을 때 `a`에서 갈 수 있는 캠프 수는 기존 연결 요소만으로 결정됩니다.

- `a`와 `b`가 **같은** 연결 요소에 있으면 → 그 요소의 크기
- **다른** 요소에 있으면 → 두 요소의 크기 합

따라서 그래프를 **한 번만** 탐색해 각 정점이 속한 요소 번호 `comp[v]`와 요소별 크기 `size[c]`를 구해 두면, 계획마다 O(1)에 답할 수 있습니다.

1. 인접 리스트를 만들고, 방문하지 않은 정점마다 BFS 로 같은 요소의 정점들에 요소 번호를 붙이며 크기를 셉니다.
2. 각 계획 `[a, b]`: `comp[a] == comp[b]`이면 `size[comp[a]]`, 아니면 `size[comp[a]] + size[comp[b]]`.

## 주의할 점
- `a = b`인 계획은 자동으로 "같은 요소" 경우에 들어가므로 따로 처리할 필요가 없습니다.
- 중복 다리와 자기 자신으로 가는 다리는 방문 표시 덕분에 요소 구성에 영향이 없습니다.
- 요소 번호 배열 `comp`를 `-1`로 초기화해 "아직 요소가 정해지지 않음"을 표현하면 별도의 `visited` 배열이 필요 없습니다.
- 다리가 한 줄로 길게 이어진 입력에서는 재귀 DFS 깊이가 n 까지 커질 수 있으니 큐 기반 BFS 를 쓰는 편이 안전합니다.

## 복잡도
- 시간 O(n + m + q), 공간 O(n + m)
