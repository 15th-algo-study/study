# 해설 — 장보기 순서 정하기

## 접근
가게를 들르는 순서를 정하면, 답은 "입구 → 가게 → … → 가게 → 출구" 각 구간의 최단 거리의 합입니다. 가게는 최대 7곳이라 순서는 7! = 5,040가지뿐이므로 모두 시도할 수 있습니다. 문제는 구간 거리를 구하는 비용입니다. 순서마다 구간마다 BFS를 돌리면 5,040 × 8번의 BFS(각 100만 칸)라 시간 초과입니다.

**관찰**: 필요한 거리는 "입구·가게·출구" 중 두 지점 사이의 거리뿐이고, 그런 쌍은 많아야 9 × 9개입니다. 지점마다 BFS를 **한 번씩만** 돌려 거리표를 만들어 두면, 순서를 시도할 때는 표에서 더하기만 하면 됩니다.

1. 입구와 각 가게에서 BFS를 한 번씩 돌려 `table[i][j]`(지점 i → 지점 j 최소 이동 횟수)를 채웁니다. 이동이 양방향이라 출구에서는 따로 돌릴 필요가 없습니다.
2. 입구에서 갈 수 없는 가게나 출구가 있으면 -1입니다.
3. 가게 순서를 모두 시도해(재귀 순열) `table[입구][첫 가게] + … + table[마지막 가게][출구]`의 최솟값을 구합니다. 지금까지의 합이 이미 최솟값 이상이면 더 볼 필요가 없습니다.

## 주의할 점
- 어떤 두 가게 사이의 최단 경로가 다른 가게를 지나가면, 그 가게는 그때 들른 것입니다. 이 경우에도 "지나간 가게를 그 자리에 끼운 순서"의 거리 합이 같으므로, 모든 순서를 시도하는 방식으로 정확한 답이 나옵니다.
- 출구 칸은 모든 가게를 들르기 전에 지나가도 됩니다. 출구를 벽처럼 막고 BFS를 돌리면 틀립니다.
- 가게가 0곳이면 입구에서 출구까지의 거리가 답입니다.
- 가장 가까운 가게부터 들르는 탐욕은 틀립니다. 예를 들어 `"P....S..P.E"`에서 가까운 오른쪽 가게(3칸)부터 들르면 3 + 8 + 10 = 21번이지만, 먼 왼쪽 가게부터 들르면 5 + 8 + 2 = 15번입니다.

## 복잡도
- 시간 O((p + 1) × rows × cols + p! × p) (p = 가게 수 ≤ 7), 공간 O(rows × cols)
