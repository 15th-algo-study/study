# 해설 — 탐사선 화물 싣기

## 접근
흔히 아는 0/1 배낭 풀이는 `dp[무게] = 최대 가치` 표를 무게 0 ~ `limit`까지 채웁니다. 하지만 `limit`이 10^9라 표를 만들 수조차 없습니다(`int` 10^9개 = 4GB).

**관찰**: 무게는 크지만 **가치는 작습니다.** 가치 합은 최대 100 × 1,000 = 100,000이므로, 표의 기준을 무게에서 가치로 바꿉니다.

- `minWeight[v]` = 가치 합이 **정확히** `v`가 되도록 고를 때 무게 합의 최솟값 (불가능하면 무한대)
- `minWeight[0] = 0`
- 화물 `(w, val)`마다 `v`를 **큰 쪽에서 작은 쪽으로** 내려가며
  `minWeight[v] = min(minWeight[v], minWeight[v - val] + w)`

모든 화물을 처리한 뒤 `minWeight[v] ≤ limit`인 가장 큰 `v`가 최대 가치이고, 그때의 `minWeight[v]`가 바로 "최대 가치를 내는 가장 가벼운 무게"입니다. 두 번째 답이 표에 그대로 들어 있다는 점도 이 방식의 장점입니다.

## 주의할 점
- `v`를 큰 쪽부터 갱신해야 같은 화물을 두 번 쓰지 않습니다(0/1 배낭의 1차원 표 기법). 작은 쪽부터 갱신하면 방금 갱신한 칸을 다시 써서 무한 배낭이 됩니다.
- 무게 합은 최대 100 × 10^9 = 10^11이라 `int`를 넘습니다. 표는 `long`으로 두고, 무한대는 `Long.MAX_VALUE / 2`처럼 더해도 넘치지 않는 값을 씁니다.
- 가치 비율(가치/무게)이 높은 순서로 담는 그리디는 틀립니다. 화물을 쪼갤 수 없기 때문입니다.
- 모든 부분집합(2^100)은 물론, 무게 기준 표도 시간·메모리 모두 불가능합니다.

## 복잡도
- 시간 O(n × V), 공간 O(V) (V = 가치 합 ≤ 100,000)
