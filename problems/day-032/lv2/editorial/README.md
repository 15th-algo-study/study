# 해설 — 발표 순서 정하기

## 접근
팀을 0번부터 차례로 보며 **후보 순번 중 아직 비어 있는 것**을 하나 골라 배정하고 다음 팀으로 넘어가는 백트래킹입니다.

```
count(team):
  team == n 이면 1 (모든 팀 배정 완료)
  합 = 0
  wishes[team]의 각 순번 s 에 대해 (중복은 건너뜀):
    s 가 비어 있으면: s 를 사용 표시 → 합 += count(team + 1) → 표시 해제
  return 합
```

핵심은 **배정이 불가능해지는 순간 즉시 가지를 자른다**는 점입니다. 후보가 팀마다 4개 이하이고 서로 다른 순번을 써야 하므로, 실제로 방문하는 상태 수는 n = 14에서도 수십만을 넘지 않습니다.

## 주의할 점
- 순번 1~n의 **모든 순열을 만든 뒤** 조건을 검사하는 풀이는 14! ≈ 8.7×10^10 가지라 시간 초과입니다. "불가능한 가지를 일찍 자르는 것"이 완전탐색과 백트래킹의 차이입니다.
- 후보 목록 안의 중복(예: `[2, 2, 3]`)을 그대로 세면 같은 배정을 두 번 셉니다. 팀마다 후보를 비트마스크로 바꾸거나 `boolean` 배열로 한 번씩만 보도록 하세요.
- `used[s] = true`로 표시했으면 돌아올 때 반드시 `false`로 되돌립니다(백트래킹의 "원상 복구").
- 팀 순서를 후보가 적은 팀부터 보도록 정렬하면 더 빨라지지만, 이 제한에서는 필요하지 않습니다.

## 복잡도
- 시간: 방문 상태 수 × 4. 상한은 4^n이지만 서로 다른 순번 제약 때문에 실제로는 훨씬 작습니다. 공간 O(n)
