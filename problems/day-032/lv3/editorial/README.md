# 해설 — 단체 사진에서 가려지는 쌍

## 접근
모든 쌍을 보면 O(n²) = 1.25×10^11이라 시간 초과입니다. **분할 정복(병합 정렬)**으로 셉니다.

`count(l, r)` = 구간 `[l, r]` 안에서 가리는 쌍의 수. 구간을 반으로 나누면

> `count(l, r)` = `count(l, m)` + `count(m+1, r)` + (앞 절반의 i, 뒤 절반의 j로 이루어진 쌍의 수)

마지막 항을 빠르게 세는 것이 핵심입니다. 두 절반을 각각 **정렬된 상태로 돌려받는다**고 하면(병합 정렬이 그렇게 해 줍니다), 조건 `heights[i] ≥ heights[j] + t`는 쌍의 **위치와 무관하게 값만** 보므로

- 뒤 절반을 작은 값부터 순서대로 보며, 앞 절반에서 `값 ≥ heights[j] + t`인 원소의 개수를 셉니다.
- `heights[j]`가 커질수록 기준 `heights[j] + t`도 커지므로, 앞 절반의 포인터는 한 방향으로만 움직입니다 (투 포인터). 두 절반을 합쳐 O(길이)입니다.

그런 다음 두 절반을 병합해 정렬된 구간을 돌려줍니다. 전체 O(n log n)입니다.

## 주의할 점
- `heights[j] + t`는 최대 2×10^9라 `int`를 넘칩니다. `long`으로 비교하세요.
- 쌍의 개수도 최대 n(n−1)/2 ≈ 1.25×10^11 라 `long`입니다.
- "같은 키"는 `t = 0`일 때만 쌍이 됩니다. 부등호가 `≥`임을 정확히 지키세요. 투 포인터를 쓸 때 경계 비교가 `>`가 되지 않도록 예 #3으로 확인하세요.
- 병합용 임시 배열은 한 번만 할당해 재사용합니다. 매 호출마다 새로 만들면 GC 부담이 큽니다.
- 재귀 깊이는 log₂(500,000) ≈ 19로 안전합니다.
- 좌표 압축 + 펜윅 트리로 "앞에서 지금까지 나온 값 중 `h + t` 이상인 것의 개수"를 세는 O(n log n) 풀이도 있습니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
