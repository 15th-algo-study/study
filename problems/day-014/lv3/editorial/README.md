# 해설 — 회문이 되는 블록 쌍

## 접근
관찰 1. 글자들을 배열해 회문을 만들 수 있다 ⇔ **홀수 번 나오는 글자가 많아야 하나**다. (짝수 개인 글자는 양쪽에 반씩 놓고, 홀수 개인 글자 하나만 가운데에 둘 수 있습니다.)

관찰 2. 글자별 개수의 **홀짝만** 중요하므로 묶음 하나를 26비트 정수 `mask`로 나타냅니다. `k`번 비트가 1이면 그 글자가 홀수 개라는 뜻입니다. 두 묶음을 합친 홀짝은 `mask_i ^ mask_j`입니다. 따라서 조건은

> `mask_i ^ mask_j`가 0이거나, 비트가 정확히 하나만 켜져 있다

즉 `mask_j`는 `mask_i`와 같거나, `mask_i`에서 비트 하나만 뒤집은 값이어야 합니다. 후보가 1 + 26 = 27개뿐입니다.

알고리즘:
1. 묶음마다 `mask`를 만들고 `HashMap<Integer, Integer>`로 `mask`별 개수를 셉니다.
2. 맵의 각 `(mask, c)`에 대해
   - 같은 마스크끼리: `c × (c - 1) / 2`
   - 비트 하나가 다른 마스크 `mask ^ (1 << k)`가 맵에 있으면 `c × cnt[mask ^ (1 << k)]`. 이때 두 마스크 쌍이 양쪽에서 한 번씩 세어지므로 `mask < mask ^ (1 << k)`일 때만 더합니다.

또는 묶음을 앞에서부터 보며 "앞에서 본 마스크 중 짝이 되는 것의 개수"를 27번 조회한 뒤 자신을 맵에 넣는 방법도 같은 복잡도입니다.

## 주의할 점
- 모든 쌍을 합쳐 글자 개수를 세는 O(n² × L)은 20만 개에서 시간 초과입니다.
- 답은 최대 n(n-1)/2 ≈ 2×10^10이므로 `long`입니다. 곱 `c × (c - 1)`도 `long`으로 계산하세요.
- 같은 글자가 두 번 들어 있는 묶음(`"aa"`)은 마스크가 0입니다. 마스크가 같다고 문자열이 같은 것은 아닙니다.
- 비트 하나 다른 쌍을 양쪽에서 두 번 세지 않도록 주의하세요.

## 복잡도
- 시간 O(n · L + M · 26) (M = 서로 다른 마스크 수 ≤ n), 공간 O(M)
