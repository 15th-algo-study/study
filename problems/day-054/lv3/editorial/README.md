# 해설 — 순회 공연 일정 잡기

## 접근
답이 되는 기간 `[L, R]`의 `L`은 반드시 어떤 도시의 날짜입니다. **`L`을 고정하면** 각 도시에서는 `L` 이상인 날짜 중 가장 이른 것을 고르는 것이 최선이고, 그때 `R`은 그 값들의 최댓값입니다. 그래서 `L`을 작은 값부터 차례로 늘려 가며 "도시마다 `L` 이상인 첫 날짜"를 유지합니다.

1. 각 도시의 날짜를 오름차순 정렬합니다.
2. 최소 힙에 도시마다 첫 날짜를 `(날짜, 도시, 인덱스)`로 넣고, 그중 최댓값 `curMax`를 따로 기억합니다. 이 상태가 "`L` = 힙의 최솟값"일 때의 선택이고 기간은 `[힙 최솟값, curMax]`입니다.
3. 힙에서 최솟값을 꺼냅니다. 기간 길이가 지금까지의 최선보다 **엄격히 짧으면** 갱신합니다. 꺼낸 도시의 다음 날짜를 넣고 `curMax`를 갱신합니다. 그 도시에 다음 날짜가 없으면 `L`을 더 늘릴 수 없으므로 끝냅니다.

후보 기간은 `L`이 커지는 순서로 열거되므로, 엄격한 부등호로 갱신하면 같은 길이 중 가장 이른 `L`이 남습니다.

## 주의할 점
- 모든 날짜를 한 배열에 모아 정렬한 뒤 `L` 후보마다 모든 도시를 다시 세면 O(N·k)이고, 각 시작점마다 오른쪽으로 확장하며 세는 방법은 O(N²)이라 20만 개에서 시간 초과입니다.
- 모은 배열 위에서 "모든 도시가 한 번 이상 들어간 창문"을 투 포인터로 좁히는 O(N log N) 풀이도 가능합니다. 힙 풀이는 그 창문의 왼쪽 끝을 도시별 포인터로 관리하는 것과 같습니다.
- 어떤 도시의 날짜를 다 쓰면 즉시 멈춰야 합니다. 멈추지 않고 계속 꺼내면 그 도시가 빠진 잘못된 기간이 후보가 됩니다.
- `curMax`는 힙에 넣을 때마다 `Math.max`로 올리기만 하면 됩니다. 힙에 들어 있는 값은 모두 `L` 이상이고, 꺼낸 값은 최댓값이 아니므로(최댓값이 유일한 최솟값이면 `k = 1`뿐) 줄어들 일이 없습니다.
- `k = 1`이면 가장 이른 날짜 하루가 답입니다.

## 복잡도
- 시간 O(N log N) (N = 날짜 수. 정렬 + 힙 연산), 공간 O(N)
