# 해설 — 약초 다발 묶기

## 접근
어떤 다발의 무게는 그 다발이 묶임에 **참여한 횟수**만큼 끈 길이에 더해집니다. 전체 비용 = Σ (무게 × 묶인 횟수) 이므로, 무거운 다발일수록 늦게(적은 횟수로) 묶여야 합니다.

따라서 **항상 가장 가벼운 두 다발을 먼저 묶는** 것이 최적입니다 (허프만 부호와 같은 구조입니다). 두 가벼운 다발이 가장 깊은 곳에 있지 않은 최적해가 있다면, 그 자리의 다발과 바꿔도 비용이 늘지 않음을 보일 수 있습니다.

구현은 최소 힙 하나면 됩니다.
1. 모든 무게를 최소 힙에 넣습니다.
2. 힙에 둘 이상 남은 동안: 가장 작은 둘 `a`, `b`를 꺼내 `a + b`를 비용에 더하고, `a + b`를 다시 넣습니다.

## 주의할 점
- 매번 배열을 정렬해서 앞의 둘을 묶으면 O(n² log n), 최솟값 둘을 훑어 찾아도 O(n²)이라 20만 개에서 시간 초과입니다.
- "인접한 둘을 묶는다"거나 "처음 정렬 순서대로 앞에서부터 누적한다"는 묶인 결과가 다른 다발보다 무거워지는 경우를 놓쳐 틀립니다. 묶인 다발을 **힙에 다시 넣어** 다음 선택에 참여시켜야 합니다.
- 묶인 다발의 무게는 최대 2×10^14라 `int`를 넘습니다. 힙은 `PriorityQueue<Long>`, 비용도 `long`입니다.
- `n = 1`이면 반복문에 들어가지 않아 0이 나옵니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
