# 해설 — 냉방기 가동 계획

## 접근
켜고 끄는 모든 조합은 2^n가지라 다 볼 수 없습니다. 그런데 `i`번 시간의 비용은 **직전 시간의 상태(켜짐/꺼짐)** 에만 영향을 받습니다. 그 이전의 기록이 어땠든 "직전에 켜져 있었는가"만 알면 됩니다. 그래서 시간마다 상태 두 개만 들고 다닙니다.

- `on[i]` = `i`번 시간까지 정했고 `i`번 시간에 켜져 있을 때의 최소 비용
- `off[i]` = `i`번 시간까지 정했고 `i`번 시간에 꺼져 있을 때의 최소 비용

점화식은 다음과 같습니다.

- `on[i] = power[i] + min(on[i-1], off[i-1] + start)` — 직전에 꺼져 있었다면 기동 비용
- `off[i] = heat[i] + min(on[i-1], off[i-1])` — 끄는 데는 비용이 없음

시작 전에는 꺼져 있으므로 `on[-1] = ∞`, `off[-1] = 0`으로 시작하고, 답은 `min(on[n-1], off[n-1])`입니다. 직전 값만 쓰므로 변수 두 개로 충분합니다.

## 주의할 점
- 시간마다 `power[i]`와 `heat[i]` 중 싼 쪽을 고르는 탐욕은 기동 비용 때문에 틀립니다(예 #2). 잠깐 끄면 다시 켤 때 비용이 들기 때문입니다.
- 비용 합은 최대 약 2 × 10^14이므로 `long`을 씁니다. ∞는 `Long.MAX_VALUE`를 그대로 쓰면 더할 때 넘치므로 `Long.MAX_VALUE / 4`처럼 여유를 둡니다.
- 0번 시간에 켜는 것도 "꺼진 상태에서 켜는 것"이라 기동 비용이 듭니다. `off[-1] = 0`, `on[-1] = ∞`로 두면 자연스럽게 처리됩니다.

## 복잡도
- 시간 O(n), 공간 O(1)
