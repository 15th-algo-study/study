# 해설 — 느린 재귀 함수 고치기

## 접근
`calc(10)`은 `calc(9)`와 `calc(5)`를 부르고, `calc(9)`는 또 `calc(8)`과 `calc(4)`를 부릅니다. `calc(5)`, `calc(4)` 같은 값이 여러 갈래에서 몇 번이고 다시 계산됩니다. 호출 횟수가 결과값만큼 늘어나서 `n = 1000`만 되어도 1,000억 번이 넘습니다.

**메모이제이션**: 한 번 계산한 `calc(k)`를 배열 `memo[k]`에 적어 두고, 다시 불리면 계산하지 않고 적어 둔 값을 돌려줍니다.

```java
int calc(int k) {
    if (k <= 1) return 1;
    if (memo[k] != -1) return memo[k];      // 이미 계산함
    return memo[k] = (calc(k - 1) + calc(k / 2)) % MOD;
}
```

이제 `calc(k)`마다 실제 계산은 한 번뿐이라 전체 O(n)입니다.

같은 내용을 반복문으로 쓸 수도 있습니다. `calc(k)`는 더 작은 `k - 1`, `k / 2`만 쓰므로 `memo[0]`, `memo[1]`부터 차례로 채우면 됩니다.

```java
memo[1] = 1;
for (int k = 2; k <= n; k++) memo[k] = (memo[k - 1] + memo[k / 2]) % MOD;
```

## 주의할 점
- "아직 계산하지 않음"을 나타낼 값이 필요합니다. 나머지 연산 결과는 0이 될 수도 있으므로 `-1`로 채워 두는 편이 안전합니다(`Arrays.fill`).
- 두 값은 각각 1,000,000,007 미만이므로 합은 약 2 × 10^9로 `int` 최댓값(약 2.147 × 10^9) 안입니다. 원래 함수와 똑같이 더한 뒤 나머지를 구하면 됩니다.
- 재귀 버전은 호출 깊이가 `n`까지 깊어집니다. 이 문제의 범위에서는 괜찮지만, 훨씬 큰 `n`이라면 반복문 버전이 안전합니다.

## 복잡도
- 시간 O(n), 공간 O(n)
