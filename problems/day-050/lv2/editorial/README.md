# 해설 — 번호 타일 이어 붙이기

## 접근
두 타일 `a`, `b` 가운데 어느 것을 앞에 둘지는 **`a + b`와 `b + a`를 비교**해서 정합니다. `a + b`가 (문자열로) 더 크면 `a`가 앞입니다. 이 비교자로 전체를 정렬한 뒤 이어 붙이면 답입니다.

왜 맞는지(교환 논법): 모든 타일 수는 같으므로 결과 길이는 순서와 무관하게 같고, 문자열 비교가 곧 수의 크기 비교입니다. 어떤 순서에서 이웃한 두 타일 `a`(앞), `b`(뒤)가 `a + b < b + a`라면 둘만 바꿔도 앞뒤 부분은 그대로이고 가운데가 커지므로 전체 수가 커집니다. 따라서 최적 순서에는 그런 이웃 쌍이 없고, 그것은 곧 위 비교자로 정렬된 순서입니다. 이 비교자가 일관된 순서(추이적)를 이룬다는 점은 `a + b ≥ b + a`가 "`a`를 `10^|b|`배 하고 `b`를 더한 값"의 비교, 즉 `a / (10^|a| − 1) ≥ b / (10^|b| − 1)`과 같다는 사실에서 나옵니다. 이 값은 타일마다 정해지는 수이므로 그 크기 순서가 바로 정렬 순서입니다.

### 가짜 그리디
- "수가 큰 타일부터": 예 #1에서 34가 9보다 앞에 와서 틀립니다.
- "문자열 사전 역순": 예 #1에서 "30"이 "3"보다 앞에 오고, 예 #2에서 "121"이 "12"보다 앞에 와서 틀립니다.

## 주의할 점
- 결과는 최대 180만 글자입니다. `String`을 `+=`로 이어 붙이면 O(n²)이므로 `StringBuilder`를 쓰세요.
- 비교자는 `(a, b) -> (b + a).compareTo(a + b)`처럼 내림차순으로 씁니다. 길이가 9 이하라 `a + b`는 18자리이므로 `Long.parseLong`으로 수로 비교해도 됩니다.
- 첫 글자가 0인 타일이 없으므로 결과가 0으로 시작하는 경우는 없습니다.
- 정렬 없이 "남은 타일 중 앞에 올 최선을 매번 고르는" 선택 정렬 방식은 O(n²)이라 20만 장에서 시간 초과입니다.

## 복잡도
- 시간 O(n log n × L) (L ≤ 18, 비교 비용), 공간 O(n × L)
