# 해설 — 장르가 딱 k가지인 플레이리스트 구간

## 접근
"정확히 `k`가지"는 구간을 늘릴 때 단조롭게 변하지 않아 투 포인터를 바로 쓰기 어렵습니다. 대신 **"`k`가지 이하"**인 구간 수는 단조롭습니다: 구간을 늘리면 장르 수는 줄지 않습니다.

핵심 관찰:

> (정확히 `k`가지인 구간 수) = (`k`가지 이하인 구간 수) − (`k − 1`가지 이하인 구간 수)

`atMost(t)`는 투 포인터로 셉니다.

- 오른쪽 끝 `right`를 한 칸씩 늘리며 그 장르의 등장 횟수를 올립니다. 처음 보는 장르면 종류 수 +1.
- 종류 수가 `t`를 넘으면 왼쪽 끝 `left`를 올리며 횟수를 내립니다. 0이 되면 종류 수 −1.
- 이제 `[left, right]`는 끝이 `right`이면서 조건을 만족하는 **가장 긴** 구간이고, 끝이 `right`인 유효 구간은 시작이 `left..right`인 `right − left + 1`개입니다. 이 값을 더합니다.

`atMost(k) − atMost(k − 1)`이 답이고, `atMost(0) = 0`입니다.

## 주의할 점
- 장르 번호가 최대 10^6이므로 등장 횟수는 길이 10^6 + 1인 `int` 배열로 셉니다. 두 번 호출하므로 배열을 새로 만들거나 0으로 되돌립니다.
- 답과 `atMost`의 결과는 `long`입니다. 모두 같은 장르 20만 곡에 `k = 1`이면 약 2 × 10^10입니다.
- `k`가 전체 장르 수보다 크면 두 값이 같아 0이 됩니다. 따로 처리하지 않아도 됩니다.
- 시작점마다 오른쪽으로 늘리며 종류 수를 세는 O(n²) 풀이는 `k`가 크거나 장르가 하나뿐인 large 케이스에서 시간 초과입니다.

## 복잡도
- 시간 O(n + 장르 번호 범위), 공간 O(장르 번호 범위)
