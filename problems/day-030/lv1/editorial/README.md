# 해설 — 수학여행 조 편성

## 접근
학생이 20명, 조원이 최대 5명이므로 조합은 최대 C(20, 5) = 15,504가지뿐입니다. 조합을 모두 만들어 보면 됩니다. 다만 조합마다 다툰 기록 100만 개를 처음부터 훑으면 15,504 × 10^6번이라 시간 초과이므로, 기록을 먼저 **`fought[a][b]` 표(`n`×`n`)에 한 번만 정리**합니다.

1. 모든 `[a, b]`에 대해 `fought[a][b] = fought[b][a] = true`.
2. 재귀로 조합을 만듭니다. `pick(start, chosenCount)`: `start` 이상의 학생 중 다음 조원을 고릅니다. 학생 `s`를 고르기 전에 **이미 고른 조원들과 `fought` 표를 확인**해 다툰 적이 있으면 건너뜁니다(가지치기).
3. `r`명을 다 고르면 1가지로 셉니다.

조합 하나를 검사하는 비용이 최대 C(5, 2) = 10번의 표 조회라 전체는 아주 빠릅니다.

## 주의할 점
- 조합은 순서를 구별하지 않으므로 항상 **번호가 커지는 순서**로만 고릅니다(`start` 이상). 순열로 만들면 같은 조가 `r!`번 세어집니다.
- 기록은 양방향이므로 표의 두 칸을 모두 채우거나, 조회할 때 양쪽을 모두 봐야 합니다.
- 중복 기록은 표에 같은 자리를 다시 표시할 뿐이므로 따로 처리할 필요가 없습니다.

## 복잡도
- 시간 O(f + C(n, r) · r) (f = 기록 수), 공간 O(n²)
