# 해설 — 보석 두 상자에 나누기

## 접근
상자 A에 넣을 보석의 부분집합을 모두 시도하면 2^40 ≈ 1.1×10^12가지라 불가능합니다. 가치가 10^9까지라 "합을 인덱스로 쓰는 DP"도 쓸 수 없습니다.

핵심 관찰: **보석을 앞 절반과 뒤 절반으로 나누면**, 각 절반의 부분집합 합은 2^20 ≈ 105만 개뿐입니다. A의 합은 `(앞 절반에서 고른 합 L) + (뒤 절반에서 고른 합 R)`이고, 목표는 `L + R`을 전체 합의 절반 `T/2`에 가장 가깝게 만드는 것입니다.

1. 앞 절반의 모든 부분집합 합 `L[]`, 뒤 절반의 모든 부분집합 합 `R[]`을 구합니다 (각각 비트마스크로 열거, 2^20개).
2. 둘 다 정렬합니다.
3. `L`은 앞(작은 값)에서, `R`은 뒤(큰 값)에서 두 포인터로 훑습니다. `s = L[i] + R[j]`에 대해 `|T − 2s|`로 답을 갱신하고, `2s < T`이면 `i++`(합을 키움), 아니면 `j--`(합을 줄임)합니다.

두 포인터가 맞는 이유: `L[i]`가 고정일 때 `R[j]`는 `T/2 − L[i]` 근처의 값이면 충분하고, `i`가 커질수록 필요한 `R`은 작아지므로 `j`는 한 방향으로만 움직입니다.

## 주의할 점
- 합은 최대 4×10^10이라 `long`으로 계산합니다. `T − 2s`도 `long`입니다.
- 비교를 `|T/2 − s|`로 하면 홀수 `T`에서 정수 나눗셈 때문에 어긋납니다. `|T − 2s|`로 비교하면 차이가 그대로 나옵니다(A − B = 2s − T).
- `n = 1`처럼 절반이 비는 경우에도 빈 쪽의 부분집합 합은 `{0}` 하나이므로 그대로 동작합니다.
- 부분집합 합 105만 개를 `List<Long>`에 담으면 박싱 때문에 느리고 메모리도 큽니다. `long[]`을 쓰세요.

## 복잡도
- 시간 O(2^(n/2) · n/2 + 2^(n/2) log 2^(n/2)) (열거 + 정렬), 공간 O(2^(n/2))
