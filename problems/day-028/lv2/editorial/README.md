# 해설 — 캠핑 배낭 꾸리기

## 접근
장비가 40개이므로 부분집합은 2^40 ≈ 1.1×10^12가지입니다. 비트마스크로 전부 열거하는 방법은 불가능하지만, 문제는 **답이 200만을 넘지 않는다**고 보장합니다. 즉 "넣을 수 있는 조합"은 적으니, **넣을 수 없는 조합은 아예 만들지 않는 가지치기**가 핵심입니다.

1. `weights`를 오름차순으로 정렬합니다.
2. `dfs(start, current)`: 지금까지 고른 무게 합이 `current`일 때, 인덱스 `start` 이상의 장비 중 다음에 넣을 것을 고릅니다.
   - 이 함수에 들어왔다는 것은 현재 조합이 유효하다는 뜻이므로 먼저 답을 1 늘립니다.
   - `j = start, start+1, …` 순서로 `current + weights[j] ≤ limit`이면 `dfs(j + 1, current + weights[j])`를 호출합니다.
   - `current + weights[j] > limit`인 `j`를 만나면, 정렬되어 있으므로 그 뒤의 장비는 모두 더 무겁습니다. **즉시 반복을 끝냅니다(break).**
3. `dfs(0, 0)`의 결과가 답입니다.

이 탐색에서 함수 호출 한 번은 정확히 유효한 조합 하나에 대응하므로, 호출 횟수 = 답 ≤ 2,000,000입니다. 가지치기를 하지 않으면 유효하지 않은 조합까지 들르게 되어 2^40에 가까워질 수 있습니다.

## 주의할 점
- 무게 합은 최대 4×10^10이므로 `current`는 `long`이어야 합니다.
- 정렬을 하지 않으면 `break` 대신 `continue`를 써야 하는데, 그러면 무거운 장비 뒤의 가벼운 장비를 확인하느라 유효하지 않은 가지를 많이 방문해 시간 초과가 납니다.
- 각 조합을 한 번씩만 세려면 "인덱스가 증가하는 순서"로만 고릅니다(`start` 이상).
- 같은 무게의 장비도 서로 다른 물건이므로 값으로 중복 제거하면 안 됩니다.

## 복잡도
- 시간 O(n log n + 답 × n) — 각 호출에서 반복문은 유효한 자식 수 + 1번만 돕니다, 공간 O(n) (재귀 깊이)
