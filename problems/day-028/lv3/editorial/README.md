# 해설 — 양념 가방과 요리 점수

## 접근
챙길 양념의 집합 `S`는 `k ≤ 17`이므로 2^17 = 131,072가지뿐입니다. 각 `S`마다 "필요 양념 집합이 `S`에 포함되는 레시피"의 점수를 더하면 되는데, 레시피 100만 개를 `S`마다 훑으면 131,072 × 1,000,000 ≈ 1.3×10^11번이라 시간 초과입니다.

핵심 관찰 두 가지:

1. **레시피는 필요 양념 집합(비트마스크)만 중요합니다.** 같은 마스크의 레시피는 점수를 합쳐 하나로 봅니다 → `exact[mask]` 배열(크기 2^k). 레시피 100만 개가 최대 131,072칸으로 압축됩니다. (압축만 하고 `S`마다 모든 칸을 훑으면 131,072² ≈ 1.7×10^10번이라 여전히 시간 초과입니다.)
2. `S`를 챙겼을 때의 점수 `total[S]`는 **`S`의 모든 부분집합 `sub`에 대한 `exact[sub]`의 합**입니다. 부분집합은 `sub = (sub - 1) & S` 로 큰 것부터 차례로 열거할 수 있고, 모든 `S`에 대한 부분집합 수의 총합은 3^k ≈ 1.3×10^8이라 충분합니다.

`total[S]`를 구하면 `best[|S|] = max(best[|S|], total[S])`로 "정확히 `c`종류"의 최댓값을 얻고, 마지막에 `best[c] = max(best[c], best[c − 1])`로 "최대 `c`종류"로 바꿉니다.

## 주의할 점
- 점수 합은 최대 10^6 × 10^9 = 10^15라 `long`이 필요합니다.
- 부분집합 열거에서 `sub = 0`(아무 양념도 필요 없는 레시피)을 빠뜨리기 쉽습니다. `S` 자신부터 시작해 0을 처리한 뒤 멈추는 형태로 쓰세요.
- 문자열에서 비트마스크를 만들 때 `j`번째 문자를 `j`번 비트에 대응시키면 됩니다(어느 쪽 끝을 0번으로 하든 일관되기만 하면 답은 같습니다).
- 양념을 더 챙긴다고 점수가 줄지는 않지만, "정확히 `c`종류"의 최댓값은 `c`가 커질 때 작아질 수 있으므로(예 #2의 c = 1, 2) 마지막 누적 최댓값 단계가 꼭 필요합니다.

## 복잡도
- 시간 O(n · k + 3^k), 공간 O(2^k)
