# 해설 — 세 색이 고른 구간

## 접근
두 색이라면 R을 +1, G를 -1로 두고 "누적합이 같은 두 지점 사이"를 찾는 익숙한 문제입니다. 세 색은 숫자 하나로 표현되지 않으므로 **차이 두 개를 키로** 씁니다.

`i`번 구슬까지의 색별 개수를 `r, g, b`라 할 때 키 `(r - g, r - b)`를 생각합니다. 구간 `(i, j]`에 세 색이 같은 개수로 들어 있다는 것은

> 구간 안에서 `r`, `g`, `b`가 똑같이 늘었다 ⇔ `r - g`와 `r - b`가 `i`와 `j`에서 같다

는 뜻입니다. 따라서

1. 키 `(0, 0)`이 위치 -1(아무것도 안 봄)에서 나왔다고 `HashMap`에 넣어 둡니다.
2. 구슬을 하나씩 보며 키를 갱신하고, 그 키가 **처음 나온 위치**를 맵에 저장합니다. 이미 있으면 `현재 위치 - 처음 위치`가 후보 길이입니다.

처음 나온 위치만 저장해야 길이가 최대가 됩니다.

키는 `"d1,d2"` 같은 문자열로 만들어도 되지만, 두 차이가 각각 `[-n, n]` 범위이므로 `(d1 + n) * (2n + 1) + (d2 + n)`으로 `long` 하나에 담으면 빠릅니다.

## 주의할 점
- 모든 구간을 보며 세 개수를 세는 O(n²)은 30만 개에서 4.5×10^10 번이라 시간 초과입니다.
- 키를 "세 개수 자체"로 두면 같은 키가 두 번 나올 수 없습니다. 반드시 **차이**로 만들어야 합니다.
- 맵에 넣을 때 이미 있는 키를 덮어쓰면 안 됩니다 (`putIfAbsent`).
- 길이가 3의 배수가 아닌 구간은 당연히 안 되지만, 따로 처리할 필요는 없습니다. 키가 같으면 자동으로 3의 배수가 됩니다.

## 복잡도
- 시간 O(n), 공간 O(n)
