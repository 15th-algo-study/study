# 해설 — 정확히 k걸음 산책

## 접근
미션마다 "k걸음 뒤에 있을 수 있는 칸 집합"을 한 걸음씩 늘려 가면 미션 하나에 O(k × 칸 수)이고, `k`가 10억이라 불가능합니다. 미션마다 BFS를 다시 돌리는 것도 20만 × 100만이라 느립니다. 두 가지 관찰로 BFS 한 번에 끝냅니다.

**관찰 1 — 홀짝(체스판 색)**: 격자를 체스판처럼 칠하면 한 걸음마다 반드시 색이 바뀝니다. 그래서 `S`에서 (r, c)로 가는 모든 걸음 수는 홀짝이 같습니다. 최단 걸음 수를 `d`라 하면, `k`걸음으로 도착하려면 `k - d`가 짝수여야 합니다.

**관찰 2 — 왕복으로 채우기**: `k ≥ d`이고 `k - d`가 짝수면, 최단 경로로 도착한 뒤 남은 걸음을 "옆 칸에 갔다가 돌아오기"(2걸음)로 채울 수 있습니다.
- `d ≥ 1`이면 최단 경로의 마지막 한 칸을 되돌아갔다 오면 되므로 항상 가능합니다.
- `d = 0`(목표가 `S`)이고 `k > 0`이면, `S`에서 한 걸음이라도 움직일 수 있어야 왕복할 수 있습니다.

정리하면 미션 `[r, c, k]`는 다음을 모두 만족할 때 `true`입니다.
1. (r, c)에 갈 수 있다 (`d ≠ -1`, 꽃밭이 아니다)
2. `k ≥ d`
3. `(k - d)`가 짝수
4. `k > d`라면 `S`에서 움직일 수 있는 칸이 하나 이상 있다

`S`에서 BFS를 한 번 돌려 모든 칸의 `d`를 구해 두면 각 미션은 O(1)입니다.

## 주의할 점
- "최단 거리 ≤ k"만 확인하면 틀립니다. 예 #1의 `[0, 1, 2]`는 거리가 1이지만 2걸음 뒤에는 (0,1)에 있을 수 없습니다.
- 제자리에 머물 수 없으므로 `S`가 꽃밭에 둘러싸이면 `k = 0`일 때만 `true`입니다(예 #2).
- `k`는 최대 10억이라 `int`로 충분하지만, 걸음을 한 단계씩 시뮬레이션하면 안 됩니다.

## 복잡도
- 시간 O(rows × cols + Q), 공간 O(rows × cols) (Q = 미션 수)
