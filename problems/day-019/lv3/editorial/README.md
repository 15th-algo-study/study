# 해설 — 열차 차량 재배열

## 1단계: 번호를 "가야 할 자리"로 바꾸기 (좌표 압축)
차량 번호 자체는 최대 10^9 지만, 중요한 것은 **각 차량이 정렬 뒤 몇 번째 자리에 가야 하는지**입니다. 인덱스 배열을 `cars` 기준으로 정렬하면, 정렬된 `k`번째 인덱스 `order[k]`의 차량은 자리 `k`로 가야 합니다. 이렇게 `target[i] = 차량 i가 가야 할 자리`를 만들면 문제는 "순열 `target`을 항등 순열로 만드는 최소 맞바꾸기 수"가 됩니다.

## 2단계: 핵심 관찰 — 답은 `n − (사이클 수)`
자리 `i`에서 `target[i]`로 화살표를 그리면 순열은 **서로 겹치지 않는 사이클**들로 나뉩니다. (예 #1: `target = [3, 0, 2, 1]` → 사이클 `0→3→1→0` 과 `2→2`.)

- 길이 `L`인 사이클은 맞바꾸기 `L − 1`번으로 모두 제자리에 보낼 수 있습니다 (사이클 안의 한 차량을 제자리로 보낼 때마다 사이클이 하나씩 짧아집니다).
- 맞바꾸기 한 번으로 사이클 수는 **최대 1만 늘어납니다** (같은 사이클의 두 원소를 바꾸면 둘로 쪼개지고, 다른 사이클의 둘을 바꾸면 하나로 합쳐집니다). 정렬된 상태는 사이클이 `n`개(모두 길이 1)이므로, 처음 사이클 수가 `c`이면 적어도 `n − c`번이 필요합니다.

따라서 답은 `Σ(L − 1) = n − c` 입니다.

## 알고리즘
1. `Integer[] order`를 `cars` 기준으로 정렬하고 `target[order[k]] = k`.
2. 방문 배열을 두고 아직 방문하지 않은 자리에서 출발해 `i → target[i] → …`를 따라가며 사이클을 하나씩 셉니다.
3. `n − c`를 돌려줍니다.

## 주의할 점
- **선택 정렬 시뮬레이션**("자리 `i`에 와야 할 차량을 찾아 바꾼다")도 같은 답을 주지만, 매번 차량을 찾는 데 O(n)이라 전체 O(n²) = 1.25×10^11 로 시간 초과입니다. `target`을 만들어 두면 "어디로 가야 하는지"를 O(1)에 알 수 있습니다.
- 버블 정렬의 교환 횟수(= 역전 쌍 수)는 **이웃한** 차량만 바꿀 때의 답이라 이 문제의 답과 다릅니다. 예 #3에서 역전 쌍은 10개지만 답은 2입니다.
- 사이클을 따라갈 때 재귀를 쓰면 길이 50만짜리 사이클에서 스택이 깊어집니다. 반복문으로 따라가세요.

## 복잡도
- 시간 O(n log n) (정렬) + O(n) (사이클 세기), 공간 O(n)
