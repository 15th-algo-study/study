# 해설 — 두루마리에서 단어 찾기

## 접근
질의 하나를 "시작 위치부터 한 글자씩 읽으며 단어를 맞춰 가는" 투 포인터로 처리하면 질의마다 O(|scroll|)이라, 질의 20만 개에 4×10^10번이 되어 시간 초과입니다. 질의당 비용을 **단어 길이에만** 비례하게 만들어야 합니다.

핵심은 **"위치 `i` 이상에서 글자 `c`가 처음 나오는 곳"을 미리 표로 만드는 것**입니다.

- `next[i][c]` = `scroll`의 인덱스 `i` 이상에서 글자 `c`가 처음 나오는 인덱스. 없으면 `n`.
- 뒤에서부터 채웁니다: `next[n][*] = n`, 그리고 `i = n-1 … 0`에 대해 `next[i] = next[i+1]`을 복사한 뒤 `next[i][scroll[i]] = i`.

이제 질의 `"p word"`는 `pos = p - 1`에서 시작해 단어의 글자마다

- `j = next[pos][c]`. `j == n`이면 -1.
- 아니면 `c`를 `j`에 표시하고 `pos = j + 1`로 옮깁니다.

마지막으로 표시한 인덱스에 1을 더한 값이 답입니다. 글자마다 O(1)이므로 질의당 O(|word|), 전체 O(26n + Σ|word|)입니다.

"가능한 한 앞쪽에 표시"하는 탐욕이 마지막 위치를 최소로 만든다는 점은 직관적입니다. 어떤 글자를 더 뒤에 표시해 봐야 그다음 글자를 찾기 시작하는 위치만 뒤로 밀릴 뿐이기 때문입니다.

## 주의할 점
- 표의 크기는 (n + 1) × 26 개의 `int`로 약 21MB입니다. `int[n + 1][26]`은 행마다 작은 배열이 생겨 조금 느리고 메모리도 더 쓰므로 `int[26][n + 1]`이나 1차원 배열 `int[(n + 1) * 26]`이 유리합니다.
- 같은 글자를 찾았으면 다음 글자는 **그 다음 인덱스부터** 찾아야 합니다 (`pos = j + 1`). `pos = j`로 두면 `"aa"`를 한 글자로 두 번 맞추는 오답이 납니다.
- 답은 1번부터 세는 위치이므로 인덱스에 1을 더합니다. 시작 위치 `p`도 1을 빼서 인덱스로 바꿉니다.
- 질의 문자열은 첫 공백의 위치만 찾으면 됩니다. `split`도 통과하지만 `indexOf(' ')` + `substring`이 더 가볍습니다.
- `scroll`이 `"aaa…ab"`이고 모든 질의가 `"1 b"`인 입력처럼, 투 포인터는 질의마다 끝까지 읽게 되어 반드시 시간 초과가 납니다.

## 복잡도
- 시간 O(26n + Σ|word|), 공간 O(26n)
