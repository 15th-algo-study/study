# 해설 — 양 끝에서 먹는 사탕

## 접근
양쪽 끝을 **들여다보고**(`peekFirst`/`peekLast`) 한쪽을 **꺼내는**(`pollFirst`/`pollLast`) 덱 연습입니다.

```
덱에 모두 넣는다
덱이 빌 때까지:
    peekFirst() <= peekLast() 이면 pollFirst(), 아니면 pollLast()
```

하나만 남았을 때는 `peekFirst()`와 `peekLast()`가 같은 원소라 `<=`에 걸려 `pollFirst()`가 되므로 따로 처리할 필요가 없습니다.

## 주의할 점
- 같을 때 왼쪽을 먹어야 하므로 비교는 `<=`(왼쪽 우선)이어야 합니다. `<`로 쓰면 같은 크기에서 오른쪽을 먹습니다.
- `Integer`끼리 `==`로 비교하면 캐시 범위(-128~127) 밖에서 틀립니다. `peekFirst() <= peekLast()`처럼 비교 연산자를 쓰면 자동으로 `int`로 풀려 안전합니다.
- 덱 없이 두 인덱스 `l`, `r`로 배열을 양쪽에서 좁혀 가도 같은 답입니다(투 포인터의 가장 단순한 형태).

## 복잡도
- 시간 O(n), 공간 O(n)
