# 해설 — 스키장 개장일 질의

## 접근
질의마다 `d + 1`일부터 차례로 훑으면 답이 없거나 멀리 있는 질의에서 O(n)씩 걸려 최악 5×10^11 번으로 시간 초과입니다.

**관찰**: 어떤 날 `d`에서 오른쪽을 볼 때, 답이 될 수 있는 날은 **"다음으로 더 높은 날" 사슬** 위에만 있습니다. `d + 1`일, 그보다 처음으로 높은 날, 그보다 처음으로 높은 날, … 이 사슬에 없는 날 `j`는 그 앞에 `snow[j]` 이상인 날이 있으므로, 어떤 `x`에 대해서도 `j`가 "첫 번째"가 될 수 없습니다.

이 사슬은 **날짜를 뒤에서부터 처리하는 단조 스택** 그 자체입니다. `i`를 넣을 때 `snow` 값이 `snow[i]` 이하인 날들을 꺼내면, 스택에는 위(최근)에서 아래로 갈수록 날짜가 커지고 적설량이 **엄격히 증가**하는 날들만 남습니다.

그래서 질의를 **오프라인**으로 처리합니다.

1. 질의를 `d`별로 묶어 둡니다.
2. `i = n - 1, …, 0` 순서로:
   - 스택에는 지금 `i + 1 … n - 1`의 사슬이 들어 있습니다. `d = i`인 질의 `[i, x]`마다, 스택에서 **적설량이 `x` 이상인 것 중 가장 위(날짜가 가장 작은 것)** 를 이분 탐색으로 찾습니다. 스택은 아래로 갈수록 값이 커지므로 "값 ≥ x인 가장 윗 원소"는 단조 구간의 경계 하나로 결정됩니다. 스택 맨 아래 값도 `x` 미만이면 -1.
   - `snow[j] <= snow[i]`인 `j`를 꺼내고 `i`를 넣습니다.

## 주의할 점
- 스택을 `int[]`로 두어야 이분 탐색이 가능합니다(`ArrayDeque`는 인덱스 접근이 없습니다). 배열 인덱스 0이 맨 아래입니다.
- `snow[j] <= snow[i]`이면 꺼내야 합니다(같은 값도 꺼냄). 같은 값이면 더 앞 날짜인 `i`가 항상 먼저 답이 되기 때문입니다.
- 질의를 `d`별로 묶을 때 `List<List<Integer>>`를 100만 개 만들면 무겁습니다. 질의 인덱스를 `d` 기준으로 정렬하거나, 카운팅 정렬식 버킷(`head`/`next` 배열)으로 묶으면 가볍습니다.
- 희소 테이블 + 이분 탐색 같은 다른 풀이도 가능하지만, 이 문제의 핵심은 "후보는 사슬 위에만 있다"는 관찰입니다.

## 복잡도
- 시간 O((n + q) log n), 공간 O(n + q)
