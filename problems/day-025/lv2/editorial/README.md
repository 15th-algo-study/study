# 해설 — 그림판 되돌리기

## 접근
명령마다 그림 상태를 통째로 저장해 두고 되돌리기 때 복원하면 메모리와 시간 모두 O(n²)입니다. 되돌리기를 만날 때마다 처음부터 다시 재생해도 O(n²)으로, 100만 명령에서 시간 초과입니다.

**관찰**: 어떤 명령이 최종 그림에 영향을 주는지는 **뒤에서부터** 보면 한 번에 결정됩니다. `[2, k]`는 "직전 `k`개 명령을 없었던 일로" 만드는 것이므로, 그 `k`개 안에 들어 있는 명령은 — 그리기든 되돌리기든 — 최종 결과에 아무 영향이 없습니다. 특히 **취소된 되돌리기는 아무것도 취소하지 않습니다.**

그래서 뒤에서 앞으로 훑으며 "앞으로 몇 개를 건너뛰어야 하는지" `skip`을 들고 갑니다.

```
skip = 0
for i = n-1 down to 0:
    if skip > 0: skip--, 이 명령은 무시          # 취소된 명령 (되돌리기여도 효력 없음)
    else if ops[i] 가 [2, k]: skip += k
    else: ops[i] 의 획은 최종 그림에 남는다
```

남는 획을 거꾸로 모았으므로 뒤집어서 return 하면 그린 순서가 됩니다. 이것은 "취소되지 않은 명령"만 남기는 스택을 뒤에서부터 쌓는 것과 같습니다.

## 주의할 점
- `skip`은 최대 `n`까지만 의미가 있지만 `k`를 그대로 더해도 `int` 범위(10^6 × 10^6 = 10^12?)는 넘을 수 있어 보입니다. 하지만 `skip > 0`인 동안은 더하지 않으므로 실제로는 한 번에 최대 10^6이고, `i`가 0이 되면 끝나므로 `int`로 충분합니다. 걱정되면 `long`을 쓰세요.
- 건너뛰는 명령이 되돌리기일 때 `k`를 더하면 안 됩니다. 이 실수가 가장 흔합니다(예 #2에서 틀립니다).
- 앞에서부터 상태를 들고 가며 푸는 방법도 있지만(명령 인덱스를 스택에 쌓고 되돌리기 때 `k`개를 꺼내되, 되돌리기를 꺼내면 그것이 꺼냈던 것들을 다시 넣기), 구현이 훨씬 복잡합니다. 역방향 한 줄 관찰이 핵심입니다.

## 복잡도
- 시간 O(n), 공간 O(n)
