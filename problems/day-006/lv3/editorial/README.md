# 해설 — 펜 플로터의 반복 무늬

## 접근
명령을 `k`번 그대로 실행하면 최대 5만 명령 × 10^11번이라 불가능합니다. 핵심 관찰은 두 가지입니다.

1. **한 번의 실행은 "이동량 + 회전량"으로 요약됩니다.** 시작 방향을 기준으로 프로그램을 한 번 실행하면 위치가 `(dx, dy)`만큼 바뀌고 방향이 `r`(0~3, 오른쪽 90° 단위)만큼 돕니다. 이 요약은 시작 위치와 무관하고, 시작 방향이 다르면 `(dx, dy)`를 그만큼 회전시키면 됩니다. 그러므로 프로그램을 **한 번만 파싱**하고, 이후의 실행은 요약값으로 O(1)에 처리합니다.
2. **4번 실행하면 방향이 처음으로 돌아옵니다.** 회전은 90° 단위이므로 `4r`은 항상 360°의 배수입니다. 따라서 4번 실행의 효과는 순수한 평행 이동 `(X4, Y4)`이고, 이것은 몇 번을 반복해도 같습니다.

따라서
- 요약값 `(dx, dy, r)`을 구하고,
- 요약값으로 1, 2, 3, 4번 실행한 뒤의 위치를 구해 4번 뒤의 위치를 `(X4, Y4)`로 두면,
- 답은 `(k / 4) × (X4, Y4) + (k % 4번 실행한 뒤의 위치)` 입니다.

방향은 0(위), 1(오른쪽), 2(아래), 3(왼쪽)으로 두고, 벡터 `(x, y)`를 오른쪽으로 90° 돌리면 `(y, -x)`가 됩니다.

## 주의할 점
- 한 번 실행의 이동량은 최대 5×10^6, `k/4`는 최대 2.5×10^10이므로 곱은 `long`이 필요합니다. `int`로 곱하면 넘칩니다.
- `L<n>`, `R<n>`의 `n`은 4로 나눈 나머지만 의미가 있습니다. 왼쪽 회전은 `(dir + 3n) % 4` 또는 `Math.floorMod(dir - n, 4)`로 처리하세요.
- 요약값을 구한 뒤 `k`번 반복문을 도는 풀이는 10^11번이라 역시 시간 초과입니다. 4번 주기를 꼭 써야 합니다.
- 명령은 한 글자 뒤에 숫자가 1~3자리 붙어 있으므로 `charAt`으로 글자를 읽고 숫자를 직접 누적하면 `split` 없이 빠르게 파싱됩니다.

## 복잡도
- 시간 O(|program|), 공간 O(1)
