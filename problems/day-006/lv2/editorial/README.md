# 해설 — 문서 구조 검사기

## 접근
괄호 짝 맞추기와 같은 구조입니다. 열린 태그 이름을 **스택**에 쌓고, 닫는 태그가 나오면 스택 맨 위와 이름을 비교합니다.

문서를 앞에서부터 한 번 훑습니다.
1. `<`를 만나면 짝이 되는 `>`의 위치를 찾아 태그 하나를 통째로 읽습니다. (`indexOf('>', i)`)
2. `</name>`이면: 스택이 비었거나 맨 위 이름이 다르면 -1. 같으면 pop.
3. `<name/>`이면: 깊이는 `스택 크기 + 1`. 최댓값만 갱신하고 스택은 그대로.
4. `<name>`이면: push. 깊이는 push 후의 스택 크기.
5. 글자는 건너뜁니다.

끝났을 때 스택이 비어 있지 않으면 -1, 비어 있으면 기록한 최대 깊이가 답입니다.

## 주의할 점
- **가장 안쪽 짝 `<x>…</x>`를 찾아 지우는 일을 반복**하는 풀이는 한 번에 O(n)이고 짝 수만큼 반복하므로 O(n²)입니다. 길이 100만이면 시간 초과입니다. 스택으로 한 번만 훑으세요.
- 재귀로 태그 안을 내려가는 파서는 중첩이 10만 겹을 넘으면 `StackOverflowError`가 납니다. 명시적 스택을 쓰세요.
- 태그 이름은 `substring`으로 잘라 `equals`로 비교합니다. `==`로 비교하면 안 됩니다.
- 닫는 태그를 처리할 때 스택이 비어 있는지 먼저 확인하세요 (`"</a>"`처럼 여는 태그 없이 닫히는 경우).
- `-1`로 끝나더라도 "틀린 지점" 이후는 볼 필요가 없으니 바로 return 해도 됩니다.

## 복잡도
- 시간 O(n), 공간 O(n) (최대 중첩 깊이만큼의 스택)
