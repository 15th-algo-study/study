# 해설 — 점수판 리모컨

## 접근
점수판에 표시된 수 하나를 **정점**, 버튼 한 번을 **길이 1인 간선**으로 보면 0 ~ 999,999의 100만 개 정점이 있는 그래프가 됩니다. 정점마다 나가는 간선은 `x + 1`, `2x`, `뒤집기(x)` 세 개뿐이므로 인접 리스트를 만들 필요 없이 그때그때 계산합니다.

"최소 몇 번"은 간선 길이가 모두 1인 그래프의 최단 거리이므로 BFS로 구합니다. 핵심은 **출발점이 하나**라는 점입니다. `start`에서 BFS를 한 번만 돌려 모든 수의 최소 횟수를 배열에 적어 두면, 각 `targets[i]`는 배열에서 바로 꺼내 답할 수 있습니다.

뒤집기는 10으로 나눈 나머지를 차례로 붙여 `r = r * 10 + x % 10`으로 계산합니다. 수로 계산하면 맨 앞의 0은 저절로 사라집니다. `Integer.parseInt(new StringBuilder(String.valueOf(x)).reverse().toString())`처럼 문자열로 해도 됩니다.

## 주의할 점
- 목표마다 BFS를 다시 돌리면 목표 20만 개 × 정점 100만 개라 시간 초과입니다. 출발점이 같으니 BFS는 한 번이면 충분합니다.
- 999,999를 넘는 수로 가는 버튼은 누를 수 없습니다. `2x`가 범위를 넘는지 먼저 확인하고 배열에 접근하세요(최대 1,999,998이라 `int`로는 넘치지 않습니다).
- 방문 여부를 `List.contains` 등으로 확인하면 한 번에 O(정점 수)라 느립니다. 크기 100만의 `int[]` 배열 하나로 거리와 방문 여부를 함께 관리합니다.
- 0을 뒤집으면 0, `x = 0`에서 `×2`도 0이므로 같은 정점으로 돌아오는 간선이 있습니다. 이미 방문한 정점은 건너뛰면 문제없습니다.

## 복잡도
- 시간 O(M + Q) (M = 1,000,000, Q = `targets`의 길이, 뒤집기는 자릿수 6번), 공간 O(M)
