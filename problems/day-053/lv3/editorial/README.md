# 해설 — 양봉장 벌통 무게의 이동 중앙값

## 접근
"흘러드는 값의 중앙값"은 최대 힙 `low`(작은 쪽 절반)와 최소 힙 `high`(큰 쪽 절반)로 풀 수 있습니다. 창문이 미끄러지면 **값이 빠져나가기도** 하는데, 자바 힙은 맨 위가 아닌 원소를 지울 수 없으므로 **지연 삭제**를 결합합니다.

- `delayed`: 값 → "아직 힙에 남아 있지만 이미 창문을 떠난 개수". 값은 중복될 수 있으므로 개수로 셉니다.
- `lowSize`, `highSize`: 각 힙의 **유효한**(떠나지 않은) 원소 수. 힙의 `size()`는 쓰레기를 포함하므로 믿지 않습니다.
- 불변식: `low`의 유효 원소 ≤ `high`의 유효 원소, `lowSize == highSize` 또는 `lowSize == highSize + 1`. 그러면 중앙값(짝수면 작은 쪽)은 항상 `low.peek()`입니다.

연산
1. **추가 x**: `x ≤ low.peek()`이면 `low`에, 아니면 `high`에 넣고 유효 수를 올린 뒤 균형을 맞춥니다.
2. **제거 x**: `delayed[x]++`. `x ≤ low.peek()`이면 `x`는 `low`에 있는 것이므로 `lowSize--`, 아니면 `highSize--`. `x`가 마침 그 힙의 맨 위라면 바로 쓰레기를 걷어 냅니다(`prune`). 그 뒤 균형을 맞춥니다.
3. **prune(힙)**: 맨 위 값이 `delayed`에 있으면 개수를 줄이며 `poll`하기를 반복합니다. 이렇게 하면 두 힙의 **맨 위는 항상 유효한 값**입니다.
4. **균형**: `lowSize > highSize + 1`이면 `low`의 맨 위를 `high`로, `lowSize < highSize`이면 `high`의 맨 위를 `low`로 옮기고, 옮긴 쪽 힙을 `prune`합니다. 맨 위가 유효하므로 옮겨지는 값도 유효합니다.

같은 값이 두 힙에 모두 있을 때 "어느 쪽 x를 지운 것으로 볼지"는 상관없습니다. `x == low.peek()`이면 `low`에 유효한 x가 확실히 있으므로 `low` 쪽을 줄이면 항상 모순 없는 상태가 됩니다.

## 주의할 점
- 창문마다 `k`개를 복사해 정렬하면 O(n·k log k) ≈ 10^10이라 시간 초과입니다. 정렬된 리스트에 끼우고 빼는 방법도 O(n·k)입니다.
- 힙의 `size()`로 균형을 판단하면 쓰레기 때문에 틀립니다. 반드시 유효 개수를 따로 셉니다.
- `prune`은 맨 위만 걷어 내므로 힙 깊은 곳의 쓰레기는 남지만, 전체 `poll` 횟수는 넣은 횟수를 넘지 않아 상각 O(log n)입니다.
- `k = 1`이면 매 창문의 값 자체가 답입니다. 일반 코드로도 처리되지만 경계 확인용으로 떠올려 두세요.

## 복잡도
- 시간 O(n log n), 공간 O(n)
