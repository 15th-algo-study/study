# 해설 — 습지 한 칸 메우기

## 접근
물 칸마다 메워 보고 BFS 로 육지 크기를 재면 (물 칸 수) × (격자 크기) = (3×10^6)² 급이라 불가능합니다. **관찰**: 물 칸 하나를 메웠을 때 생기는 육지는 "그 칸 + 상하좌우에 닿아 있는 **기존 육지들**"의 합집합입니다. 기존 육지의 크기는 메우기 전에 미리 구해 둘 수 있습니다.

1. **육지 번호 매기기.** 모든 땅 칸에 대해 BFS 로 연결 요소를 찾고, 각 칸에 육지 번호 `id[r][c]`를, 번호별 크기를 `size[id]`에 저장합니다.
2. **물 칸마다 O(1)로 계산.** 물 칸 `(r, c)`의 네 이웃이 속한 육지 번호를 모아 **서로 다른 번호**의 크기만 더하고 1(메운 칸)을 더합니다. 같은 육지가 두 방향에서 닿아 있으면 한 번만 더해야 합니다. 이웃은 최대 4개이므로 번호 4개를 비교해 중복을 거르면 됩니다.
3. 물 칸이 없으면 메울 수 없으므로 전체 땅 칸 수(= 가장 큰 육지)가 답이고, 물이 있으면 2에서 구한 최댓값이 답입니다. 2의 최댓값은 메우지 않았을 때의 최대 육지보다 항상 크거나 같으므로(어떤 육지에 닿은 물 칸을 메우면 그 육지 + 1), 물이 하나라도 있으면 2의 값만 보면 됩니다. 단, 땅이 전혀 없으면 1입니다.

## 주의할 점
- 2에서 **같은 육지를 두 번 더하는 실수**가 가장 흔합니다. 예: `["LLL", "LWL", "LLL"]`의 가운데를 메우면 네 이웃이 모두 같은 육지 하나이므로 8 + 1 = 9이지 8×4 + 1이 아닙니다.
- 격자가 최대 300만 칸이므로 번호 배열은 `int[rows * cols]` 하나로 두고, BFS 큐도 `int[]`로 만드세요. 재귀 flood fill 은 전부 땅인 입력에서 깊이 300만이 되어 StackOverflowError 가 납니다.
- 이웃 번호의 중복 제거에 `HashSet`을 쓰면 물 칸마다 객체를 만들어 느립니다. 번호 최대 4개를 변수나 작은 배열에 담아 비교하세요.

## 복잡도
- 시간 O(rows × cols), 공간 O(rows × cols)
