# 해설 — 조립식 책상 높이 맞추기

## 접근
네 겹 반복문은 1600^4 ≈ 6.6×10^12번, 세 겹 + 해시 조회도 1600^3 ≈ 4.1×10^9번이라 시간 초과입니다.

핵심 관찰: `a + b + c + d = target`은 **`(a + b) = target − (c + d)`**와 같습니다. 즉 네 부품을 **둘씩 나누어** 반반 열거하면, 각각 1600² = 2,560,000개의 합만 다루면 됩니다.

1. `ab[]` = 상판과 다리의 모든 합 (2,560,000개), `cd[]` = 받침과 바퀴의 모든 합.
2. 두 배열을 정렬합니다.
3. `ab`는 앞(작은 값)에서, `cd`는 뒤(큰 값)에서 두 포인터로 훑습니다.
   - `ab[i] + cd[j] < target`이면 `i++`, `>`이면 `j--`.
   - 같으면 `ab`에서 그 값이 연속으로 몇 개(`x`), `cd`에서 그 값이 연속으로 몇 개(`y`)인지 세고 `x × y`를 답에 더한 뒤 두 묶음을 모두 건너뜁니다.

## 주의할 점
- 부품 높이가 10^9까지라 두 부품의 합은 `int`를 넘습니다. `ab`, `cd`는 `long[]`이어야 하고 답도 `long`입니다(최대 1600^4 ≈ 6.6×10^12).
- 같은 합이 여러 번 나올 때 **묶음 크기의 곱**을 더해야 합니다. 하나씩 짝지어 세면 틀립니다.
- `HashMap<Long, Integer>`로 `ab`의 빈도를 세고 `cd`를 조회해도 되지만, 원소 256만 개를 박싱하면 메모리·시간이 꽤 들어 정렬 + 두 포인터가 안정적입니다.

## 복잡도
- 시간 O(n² log n) (정렬), 공간 O(n²)
