# 해설 — 진주 크기 등급 조회

## 접근
질문마다 전체를 세면 O(nq) = 4 × 10^10으로 시간 초과입니다. 먼저 `sizes`를 **정렬**해 두면 "`lo` 이상 `hi` 이하"인 원소는 연속한 구간이 되고, 그 개수는

> (`hi` 이하인 원소의 개수) − (`lo` 미만인 원소의 개수)

입니다. 두 값은 각각 이분 탐색으로 구합니다.

- `lowerBound(x)`: `x` 이상인 첫 인덱스 = `x` 미만인 원소의 개수
- `upperBound(x)`: `x` 초과인 첫 인덱스 = `x` 이하인 원소의 개수
- 답 = `upperBound(hi) − lowerBound(lo)`

둘 다 "조건을 만족하는 첫 위치"를 찾는 같은 틀로, 비교 연산만 `>=` / `>`로 다릅니다.

## 주의할 점
- 같은 값이 여러 개이므로 `Arrays.binarySearch`는 쓸 수 없습니다 (어느 것을 돌려줄지 정해지지 않음). 직접 lower/upper bound를 구현하세요.
- 이분 탐색의 범위는 `lo = 0`, `hi = n`(배열 길이)입니다. 모든 원소가 `x`보다 작으면 `n`이 나와야 "미만 개수 = n"이 됩니다.
- `mid = (lo + hi) / 2`는 인덱스라 넘치지 않지만, 값 비교에서 `int` 범위(10^9)는 안전합니다.

## 복잡도
- 시간 O((n + q) log n), 공간 O(q)
