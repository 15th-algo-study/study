# 해설 — 레고 블록 한 줄 바꾸기

## 접근
구간 `[l, r]`을 한 색으로 만들려면 그 구간에서 **가장 많은 색을 남기고 나머지를 바꾸는 것**이 최선입니다. 즉 구간이 가능하려면

> (구간 길이) − (구간 안 최다 색의 개수) ≤ `k`

입니다. 문제는 "이 조건을 만족하는 가장 긴 구간"이고, 슬라이딩 윈도우로 풉니다.

1. 색별 개수 `cnt`와 창 안 최다 개수 `maxFreq`를 유지하며 오른쪽 끝 `r`을 늘립니다. `cnt[colors[r]]++` 후 `maxFreq = max(maxFreq, cnt[colors[r]])`.
2. `(r − l + 1) − maxFreq > k`이면 왼쪽 끝을 하나 올립니다 (`cnt[colors[l]]--`, `l++`).
3. 매 단계 `r − l + 1`로 답을 갱신합니다.

**핵심 관찰**: 왼쪽 끝을 올릴 때 `maxFreq`를 다시 계산하지 않아도 됩니다. `maxFreq`가 실제보다 크게 남아 있어도, 그 값은 *과거에 실제로 달성했던* 창 길이의 조건이므로 답을 부풀리지 않습니다. 더 긴 답이 나오려면 어차피 `maxFreq`가 진짜로 커져야 합니다. 그래서 창은 줄어들지 않고 "유지되거나 1씩 커지기만" 하며, 마지막 창의 길이가 답입니다.

## 주의할 점
- 색의 종류가 최대 50만이라, 왼쪽 끝을 옮길 때마다 `maxFreq`를 모든 색에 대해 다시 구하면 O(n × 색 수)로 시간 초과입니다. 위 관찰로 다시 계산하지 않거나, 색별 위치 목록을 만들어 색마다 투 포인터를 돌려도(합쳐서 O(n)) 됩니다.
- 왼쪽 끝 `l`마다 오른쪽으로 늘려 보는 O(n × 창 길이) 풀이는 `k`가 큰 large 케이스(창 길이 20만 이상)에서 10^11번 연산이라 시간 초과입니다.
- `k = 0`이면 같은 색이 이미 연속한 최장 길이, `k ≥ n`이면 `n`이 자연스럽게 나옵니다.

## 복잡도
- 시간 O(n), 공간 O(n + 색 수)
