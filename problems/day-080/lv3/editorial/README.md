# 해설 — 검문소를 세울 교차로

## 접근
교차로마다 "그 교차로를 막고 다익스트라를 다시 돌려 최단 시간이 늘어나는지" 보면 정확하지만, 최단 경로 위 교차로가 수천 개면 다익스트라를 수천 번 돌려야 해서 시간 초과입니다. 다익스트라 **두 번**으로 끝내는 관찰이 필요합니다.

### 1. 최단 경로 위의 정점과 간선
- `d1[v]`: 0번에서 `v`까지 최단 시간, `d2[v]`: `v`에서 `n − 1`번까지 최단 시간 (양방향 도로이므로 `n − 1`번에서 다익스트라)
- `D = d1[n − 1]`
- 정점 `v`가 어떤 최단 경로 위에 있다 ⇔ `d1[v] + d2[v] = D`
- 도로 `(u, x, t)`를 `u → x` 방향으로 쓰는 최단 경로가 있다 ⇔ `d1[u] + t + d2[x] = D` (이때 `d1[x] = d1[u] + t`)

### 2. 시간 축으로 보기
모든 최단 경로는 `d1` 값이 0에서 D까지 **계속 커지며** 진행합니다(도로 시간이 양수). 최단 경로 위 정점 `v`에 대해, 차량이 `v`를 피하는 방법은 둘뿐입니다.
- **같은 시각의 다른 정점**을 지난다: `d1[w] = d1[v]`인 다른 최단 경로 정점 `w`가 있으면, `w`를 지나는 최단 경로는 `v`를 지날 수 없습니다(한 경로에서 `d1`은 엄격히 증가).
- **그 시각을 건너뛰는 간선**을 탄다: 최단 경로 간선 `u → x`가 `d1[u] < d1[v] < d1[x]`이면, 그 간선을 쓰는 최단 경로는 `v`를 지나지 않습니다.

반대로 둘 다 없으면, 어떤 최단 경로든 `d1` 값이 `d1[v]`를 지나는 순간 정확히 그 값을 가진 정점에 서야 하고(건너뛰는 간선이 없으므로), 그런 정점은 `v`뿐이므로 반드시 `v`를 지납니다.

### 3. 구현
1. 최단 경로 위 정점들의 `d1` 값을 정렬·중복 제거해 번호를 매깁니다(좌표 압축).
2. 값마다 정점 수 `cnt[]`를 셉니다.
3. 최단 경로 간선 `u → x`마다 번호 구간 `(idx(u), idx(x))`의 **안쪽**을 차분 배열로 +1 합니다.
4. 누적합 뒤 `cnt == 1`이고 덮인 횟수가 0인 정점(0번, `n − 1`번 제외)이 답입니다.

## 주의할 점
- "같은 시각에 최단 경로 정점이 하나뿐"만 확인하면 예 #3에서 틀립니다. 시각을 건너뛰는 간선도 봐야 합니다.
- 최단 경로 수를 큰 소수로 나눈 나머지로 세어 `ways1[v] × ways2[v] ≡ ways1[n−1]`인지 보는 방법도 있지만, 나머지가 우연히 같아질 위험이 있습니다. 위 방법은 결정적입니다.
- 거리는 최대 약 2 × 10^14라 `long`입니다. 도달 불가(INF)인 정점은 합을 구하기 전에 걸러야 넘치지 않습니다.
- 도로가 양방향이므로 간선마다 두 방향을 모두 검사합니다.

## 복잡도
- 시간 O((n + m) log m), 공간 O(n + m)
