# 해설 — 새 도로 후보 평가

## 접근
후보마다 도로를 더해 플로이드–워셜을 다시 돌리면 후보 500개 × 800³ ≈ 2.6 × 10^11번이라 시간 초과입니다.

**관찰**: 새 도로 `(a, b, len)` 하나를 더했을 때 `i → j` 최단 경로가 새 도로를 쓰지 않는다면 거리는 그대로입니다. 쓴다면 최단 경로는 새 도로를 한 번만 지나므로(두 번 지나면 사이에 돌아오는 부분을 잘라 더 짧게 만들 수 있음)

- `i → a`, 새 도로, `b → j` : `dist[i][a] + len + dist[b][j]`
- `i → b`, 새 도로, `a → j` : `dist[i][b] + len + dist[a][j]`

중 하나입니다. 여기서 `dist`는 **기존 도로만으로** 구한 최단 거리입니다. 그러므로

1. 기존 도로로 플로이드–워셜을 한 번 돌려 `dist`를 구합니다.
2. 후보마다 모든 쌍 `i < j`를 보며 `min(위 두 값) < dist[i][j]`인 쌍을 셉니다.

후보 하나에 O(n²)이라 전체 O(n³ + q·n²)입니다.

## 주의할 점
- 갈 수 없는 쌍은 `dist = INF`입니다. INF를 `Integer.MAX_VALUE`로 두면 `INF + len + INF`가 넘쳐 음수가 됩니다. 실제 최단 거리는 최대 799 × 10,000 ≈ 8 × 10^6이므로 INF를 10억 정도로 두면 `INF + 10,000 + INF`도 `int` 안이고, INF가 끼면 결과가 항상 INF보다 커서 비교가 자연스럽게 맞습니다.
- "같아지는" 쌍은 세지 않으므로 `<`로 비교합니다.
- 후보끼리는 독립이므로, 후보를 평가하면서 `dist`를 고치면 안 됩니다.
- 해설 코드는 플로이드–워셜의 한 행 갱신과 후보 하나의 한 행 세기를 작은 메서드로 나눴습니다. 단순한 반복문만 담긴 작은 메서드는 JIT 가 빨리 최적화(벡터 명령 사용)해 줘서, 같은 계산이 몇 배 빨라집니다.

## 복잡도
- 시간 O(n³ + q·n²), 공간 O(n²)
