# 해설 — 솔라카의 배터리

## 접근
음수 가중치가 있으므로 다익스트라는 쓸 수 없습니다(이미 확정한 정점이 나중에 음수 간선으로 더 짧아질 수 있음). 정점이 300개뿐이고 모든 쌍 질의이므로 **플로이드–워셜**을 씁니다. 플로이드–워셜은 음수 간선이 있어도 음수 사이클만 없으면 정확합니다.

1. `dist[i][i] = 0`, 구간 `[a, b, c]`는 `dist[a][b] = min(dist[a][b], c)`, 나머지는 INF.
2. 플로이드–워셜을 돌립니다. 끝난 뒤 **`dist[k][k] < 0`이면 `k`는 음수 사이클 위에 있습니다**(자기 자신으로 돌아오는 길이 음수).
3. 질의 `[s, e]`:
   - `dist[s][e] == INF` → `"UNREACHABLE"`
   - 어떤 `k`가 `dist[k][k] < 0`이고 `dist[s][k] < INF`, `dist[k][e] < INF`이면 → `"UNBOUNDED"` (s에서 k로 가서 사이클을 원하는 만큼 돈 뒤 e로 감)
   - 아니면 `dist[s][e]`

질의가 10만 개라 질의마다 `k`를 훑으면 3 × 10^7번입니다. 그 정도도 괜찮지만, 미리 `unbounded[s][e]`를 O(n³)로 한 번 채워 두면 질의는 O(1)입니다.

## 주의할 점
- **값이 폭주합니다.** 음수 사이클이 있으면 플로이드–워셜 도중 `dist`가 단계마다 거의 두 배씩 작아져 `long`도 넘칠 수 있습니다(정점 300개면 2^300배). 갱신한 값이 아주 작은 기준값(예: −10^18)보다 작아지면 그 기준값으로 고정합니다. 음수 사이클과 무관한 쌍의 값은 최대 ±3 × 10^8이라 이 고정에 영향을 받지 않습니다.
- INF 끼리 더하지 않도록 `dist[i][k] == INF`이거나 `dist[k][j] == INF`이면 건너뜁니다. 음수 간선이 있으면 "INF + 음수 < INF"가 되어 갈 수 없는 쌍이 갈 수 있는 것처럼 보이는 버그가 생깁니다.
- `dist[s][e]`가 음수라는 것만으로 `"UNBOUNDED"`라고 하면 틀립니다(예 #1의 0 → 2처럼 그냥 음수일 수 있음). 반드시 음수 사이클을 거칠 수 있는지 봅니다.
- 질의마다 벨만–포드를 돌리면 10만 × n × m이라 시간 초과입니다.

## 복잡도
- 시간 O(n³ + m + q), 공간 O(n²)
