# [lv2] 솔라카의 배터리

태양광 자동차(솔라카) 랠리 코스에 체크포인트 `n`개(0번 ~ `n - 1`번)가 있습니다. 체크포인트 사이 구간은 모두 **한 방향**이고, 구간마다 지나는 동안의 **배터리 변화량**이 정해져 있습니다. 양수는 그만큼 배터리를 쓴다는 뜻이고, 음수는 햇빛이 잘 드는 구간이라 쓰는 것보다 충전되는 양이 많아 오히려 그만큼 배터리가 늘어난다는 뜻입니다.

솔라카는 같은 체크포인트나 구간을 몇 번이든 다시 지날 수 있습니다. 질의 `[s, e]`마다 `s`번 체크포인트에서 `e`번 체크포인트까지 가는 동안 쓰는 배터리 총량(변화량의 합)의 **최솟값**을 구하려고 합니다. 질의마다 결과를 문자열로 나타냅니다.

- 최솟값이 정해지면 그 값을 10진수 문자열로 씁니다. 예: `"-2"`, `"15"`
- `s`에서 `e`로 갈 수 없으면 `"UNREACHABLE"`
- 갈 수 있지만 총량을 얼마든지 작게 만들 수 있으면(돌수록 배터리가 늘어나는 순환로를 거쳐 갈 수 있으면) `"UNBOUNDED"`
- `s = e`이면 움직이지 않는 것(총량 0)도 하나의 방법입니다.

구간 정보 `paths`와 질의 목록 `queries`가 주어질 때, 질의 순서대로 결과를 담은 문자열 배열을 return 하도록 `solution` 함수를 완성해 주세요.

- `paths`의 원소 `[a, b, c]`는 `a`번에서 `b`번으로 가는 구간이며 배터리 변화량이 `c`입니다. 같은 두 체크포인트 사이에 구간이 여러 개이거나 `a = b`인 순환 구간이 있을 수 있습니다.

## 제한사항
- 1 ≤ `n` ≤ 300
- 0 ≤ `paths`의 길이 ≤ 30,000
- `paths`의 원소는 `[a, b, c]` 형태이며 0 ≤ `a`, `b` < `n`, −1,000,000 ≤ `c` ≤ 1,000,000
- 1 ≤ `queries`의 길이 ≤ 100,000
- `queries`의 원소는 `[s, e]` 형태이며 0 ≤ `s`, `e` < `n`

## 입출력 예

| n | paths | queries | result |
|---|---|---|---|
| 4 | [[0, 1, 5], [1, 2, -3], [0, 2, 4], [2, 3, 1]] | [[0, 2], [0, 3], [3, 0], [1, 1]] | ["2", "3", "UNREACHABLE", "0"] |
| 3 | [[0, 1, 2], [1, 0, -3], [1, 2, 7]] | [[0, 2], [2, 0], [0, 0]] | ["UNBOUNDED", "UNREACHABLE", "UNBOUNDED"] |

## 입출력 예 설명
- 예 #1
  - 0 → 2: 직접 가면 4, 0 → 1 → 2는 5 − 3 = 2 → `"2"`
  - 0 → 3: 0 → 1 → 2 → 3 = 3 → `"3"`
  - 3번에서 나가는 구간이 없습니다 → `"UNREACHABLE"`
  - 1 → 1: 제자리에 있으면 0 → `"0"`
- 예 #2: 0 → 1 → 0을 한 바퀴 돌 때마다 2 − 3 = −1씩 줄어듭니다. 0번에서 이 순환로를 원하는 만큼 돈 뒤 1 → 2로 가면 되므로 0 → 2와 0 → 0은 `"UNBOUNDED"`입니다. 2번에서 나가는 구간은 없습니다.
