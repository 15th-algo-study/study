# [lv3] 케이크 주문 처리 순서

작은 케이크 가게에 주문 `n`건이 한꺼번에 들어왔습니다. 가게에는 오븐이 하나뿐이라 주문을 **한 번에 하나씩, 쉬지 않고** 처리합니다. `i`번 주문은 만드는 데 `minutes[i]`분이 걸리고, 손님은 **주문이 완성될 때까지** 기다리는 매 1분마다 `penalties[i]`원의 할인 쿠폰을 받습니다. 즉 `i`번 주문이 시작 시각 0으로부터 `T`분 뒤에 완성되면 그 손님에게 `T × penalties[i]`원을 줍니다.

주문을 처리하는 순서를 자유롭게 정할 수 있을 때, 손님들에게 주는 **쿠폰 금액의 총합을 최소**로 만들고 그 최솟값을 return 하도록 `solution` 함수를 완성해 주세요. 총합은 `int` 범위를 넘을 수 있으므로 `long`으로 return 합니다.

## 제한사항
- 1 ≤ `minutes`의 길이 = `penalties`의 길이 = `n` ≤ 300,000
- 1 ≤ `minutes[i]` ≤ 1,000
- 1 ≤ `penalties[i]` ≤ 1,000

## 입출력 예

| minutes | penalties | result |
|---|---|---|
| [3, 1, 2] | [1, 1, 1] | 10 |
| [10, 1] | [1, 100] | 111 |
| [2, 4] | [1, 3] | 18 |

## 입출력 예 설명
- 예 #1: 쿠폰 단가가 모두 같으므로 빨리 끝나는 주문부터 처리합니다. 1분, 2분, 3분짜리 순서로 하면 완성 시각이 1, 3, 6 이고 총합은 1 + 3 + 6 = **10**입니다.
- 예 #2: 1분짜리(단가 100)를 먼저 하면 1×100 + 11×1 = **111**, 반대로 하면 10×1 + 11×100 = 1110 입니다.
- 예 #3: 4분짜리(단가 3)를 먼저 하면 4×3 + 6×1 = **18**, 2분짜리를 먼저 하면 2×1 + 6×3 = 20 입니다. 짧은 주문부터 하는 것이 항상 최선은 아닙니다.
