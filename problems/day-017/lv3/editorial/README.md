# 해설 — 케이크 주문 처리 순서

## 핵심 관찰: 이웃한 두 주문을 바꿔 보기 (교환 논법)
어떤 순서에서 **이웃한** 두 주문 A(시간 `tA`, 단가 `wA`)와 B(`tB`, `wB`)를 생각합니다. A를 먼저 하든 B를 먼저 하든 그 앞뒤 주문들의 완성 시각은 변하지 않고, 두 주문의 비용만 달라집니다. 두 주문이 시작하는 시각을 `S`라 하면

- A → B 순서: `wA(S + tA) + wB(S + tA + tB)`
- B → A 순서: `wB(S + tB) + wA(S + tB + tA)`

공통 항을 지우면 차이는 `wB·tA` 와 `wA·tB` 뿐입니다. 즉 **`tA·wB < tB·wA` 이면 A를 먼저** 하는 것이 이득입니다. 이 조건은 `tA / wA < tB / wB` 와 같습니다.

따라서 최적 순서에서는 이웃한 모든 쌍이 이 조건을 만족해야 하고, 그것은 곧 **`minutes[i] / penalties[i]` (단가 1원당 걸리는 시간) 오름차순**으로 정렬한 순서입니다. 비율이 같은 두 주문은 어느 쪽을 먼저 해도 총합이 같습니다.

## 알고리즘
1. 주문 번호 배열을 `minutes[a] * penalties[b]` 와 `minutes[b] * penalties[a]` 를 비교하는 비교자로 정렬합니다 (나눗셈 대신 **교차 곱셈**으로 정수 비교).
2. 정렬된 순서로 완성 시각을 누적하며 `완성 시각 × 단가`를 더합니다.

## 주의할 점
- "짧은 주문부터"(SPT)나 "단가 높은 주문부터"는 각각 예 #3, 예 #2에서 틀립니다. 두 값을 **함께** 봐야 합니다.
- 교차 곱은 최대 1,000 × 1,000 = 10^6 이라 `int`로 충분하지만, 총합은 완성 시각(최대 3×10^8) × 단가(1,000) × 건수라 최대 약 9×10^16 입니다. 누적 변수는 `long`이어야 합니다.
- `double`로 비율을 비교해도 이 제한에서는 통과하지만, 값이 커지면 오차로 순서가 어긋날 수 있습니다. 교차 곱셈이 정석입니다.
- 비교자는 일관되어야 합니다(`a < b`와 `b < a`가 동시에 참이 되면 `IllegalArgumentException`). 교차 곱 비교는 추이성이 있어 안전합니다.
- 이웃 교환을 직접 반복하는 버블 정렬은 O(n²)이라 30만 건에서 시간 초과입니다. 관찰로 비교 기준을 찾고 정렬 API에 맡기세요.

## 복잡도
- 시간 O(n log n), 공간 O(n)
