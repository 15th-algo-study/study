# 해설 — 커서가 있는 입력기

## 접근
텍스트를 **커서 왼쪽**과 **커서 오른쪽** 두 덩어리로 나누어 각각 스택처럼 관리하면 모든 키가 O(1)입니다.

- `left`: 커서 왼쪽 글자들. 맨 위가 커서 바로 앞 글자.
- `right`: 커서 오른쪽 글자들. 맨 위가 커서 바로 뒤 글자 (즉 뒤집힌 순서로 저장).

| 키 | 동작 |
|---|---|
| 글자 | `left.push(글자)` |
| `<` | `left`가 비어 있지 않으면 `left.pop()` |
| `[` | `left`가 비어 있지 않으면 `right.push(left.pop())` |
| `]` | `right`가 비어 있지 않으면 `left.push(right.pop())` |

끝나면 `left`를 순서대로, `right`를 거꾸로(맨 위부터) 이어 붙이면 됩니다. 스택은 `char[]`와 크기 변수만으로 구현해도 되고 `ArrayDeque<Character>`를 써도 됩니다.

## 주의할 점
- `StringBuilder.insert(cursor, ch)`, `deleteCharAt(cursor - 1)`은 커서 뒤의 글자를 전부 한 칸씩 밀기 때문에 한 번에 O(n)입니다. 글자를 쓰고 `[`로 한 칸 물러나는 일을 반복하면 항상 맨 앞에 끼워 넣게 되어 전체 O(n²)이 됩니다. 길이 100만이면 시간 초과입니다.
- `LinkedList`의 `ListIterator`로 커서를 흉내 내는 방법도 O(1)이지만, `list.add(index, x)`처럼 인덱스로 접근하면 다시 O(n)이 되니 주의하세요.
- 빈 상태에서의 `<`, `[`와 맨 뒤에서의 `]`는 무시해야 합니다. 비어 있는지 확인하지 않으면 예외가 납니다.
- 결과를 만들 때 `right`는 **뒤집힌 순서**로 들어 있으므로 맨 위부터 꺼내 붙이면 원래 순서가 됩니다.

## 복잡도
- 시간 O(n), 공간 O(n)
