# 해설 — 박람회 부스 설치

## 접근
두 가지 관찰이 필요합니다.

**관찰 1 — 어떤 작업 집합을 하기로 했다면, 마감 오름차순으로 하는 것이 최선입니다.** 마감이 늦은 작업이 마감이 이른 작업보다 앞에 있다면 둘을 바꿔도 마감을 어기지 않습니다 (교환 논법). 따라서 작업을 마감 순으로 정렬하고 그 순서로 "할지 말지"만 정하면 됩니다.

**관찰 2 — 마감 순으로 보다가 넘치면, 지금까지 고른 것 중 가장 오래 걸리는 작업을 뺍니다.** 마감 순으로 작업을 하나씩 "일단 고르고" 총 소요 시간을 더합니다. 총 시간이 지금 작업의 마감을 넘기면, 고른 작업들 중 **`dur`이 가장 큰 것 하나를 버립니다**(지금 작업일 수도 있습니다). 버린 뒤에는 총 시간이 이 작업 이전의 상태보다 작거나 같으므로 앞선 마감들도 여전히 모두 지켜집니다. 같은 개수를 유지하면서 총 시간을 가장 작게 만드는 선택이므로, 이후 작업을 넣을 여지가 가장 많습니다.

"고른 작업 중 최댓값을 꺼낸다"가 필요하므로 **최대 힙**으로 고른 작업의 `dur`을 들고 있으면 됩니다. 마지막 힙 크기가 답입니다.

이 그리디가 최적인 이유: 마감 순으로 `i`번째 작업까지 처리했을 때, 힙은 "앞 `i`개 중 고를 수 있는 최대 개수"를 유지하면서 그 개수를 이루는 집합 중 **총 시간이 최소**인 것을 들고 있습니다. 두 성질이 귀납적으로 유지됨을 보일 수 있습니다.

## 주의할 점
- 마감 순으로 "들어가면 넣고 아니면 건너뛰기"만 하면 틀립니다 (예 #2에서는 우연히 같은 답이지만, `[[6, 6], [1, 7], [1, 7], [1, 7]]`에서는 건너뛰기만 하면 2개지만 답은 3개입니다). 넘칠 때 **이미 고른 큰 작업을 되돌려 빼는** 것이 핵심입니다.
- 넘칠 때마다 고른 목록을 훑어 최댓값을 찾으면 O(n²)이라 30만 개에서 시간 초과입니다. 힙이면 O(log n)입니다.
- 총 소요 시간은 최대 3×10^14라 `long`입니다.
- 넘쳤을 때 빼는 작업이 방금 넣은 작업일 수도 있습니다. 방금 넣은 뒤에 힙에서 최댓값을 빼는 순서로 짜면 자연스럽게 처리됩니다.
- 마감이 같은 작업들의 순서는 결과에 영향을 주지 않습니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
