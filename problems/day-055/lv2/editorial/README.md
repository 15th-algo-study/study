# 해설 — 유적 발굴 자금

## 접근
자금은 **줄어들지 않습니다**(`gain ≥ 0`). 그러므로 한 번 발굴 가능해진 유적은 계속 발굴 가능하고, 매 단계에서 **지금 가능한 유적 중 `gain`이 가장 큰 곳**을 고르는 그리디가 최적입니다. (더 작은 `gain`을 먼저 골라 봤자 자금이 덜 늘어나 이후 선택지가 줄어들 뿐입니다.)

"지금 가능한 유적"의 집합은 자금이 늘수록 커지기만 하므로 두 단계로 관리합니다.
1. 유적을 `req` 오름차순으로 정렬하고 포인터 `p`를 둡니다.
2. 최대 `k`번 반복: `sites[p].req ≤ fund`인 동안 그 유적의 `gain`을 **최대 힙**에 넣고 `p`를 옮깁니다. 힙이 비었으면 더 할 수 있는 것이 없으므로 끝냅니다. 아니면 최댓값을 꺼내 `fund`에 더합니다.

각 유적은 힙에 한 번만 들어가므로 포인터는 총 `n`번만 움직입니다.

## 주의할 점
- 단계마다 유적 `n`곳을 훑어 가능한 것 중 최댓값을 찾으면 O(k·n) = 4×10^10이라 시간 초과입니다.
- `req`로 정렬만 하고 순서대로 발굴하면 틀립니다 (예 #1: `req` 순서는 0번 → 1번 → 2번인데 `k = 2`이면 0번·1번만 하게 됩니다). 힙에서 **`gain`이 큰 것**을 꺼내야 합니다.
- 자금은 최대 10^9 + 2×10^5 × 10^9 ≈ 2×10^14라 `long`입니다. `req`와 비교할 때도 `long`으로 비교하세요.
- 힙이 비었는데 `k`가 남아 있으면 바로 끝내야 합니다. 비어 있는 힙에 `poll`하면 `null`이라 `NullPointerException`이 납니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
