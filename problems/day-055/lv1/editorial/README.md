# 해설 — 도자기 가마 예약

## 접근
필요한 가마 수 = **동시에 진행 중인 예약 수의 최댓값**입니다. 예약을 시작 시각 순으로 보면서 "지금 사용 중인 가마들의 끝나는 시각"을 **최소 힙**으로 관리합니다.

1. 예약을 `start` 오름차순으로 정렬합니다.
2. 예약마다: 힙의 맨 위(가장 빨리 끝나는 가마)가 `start` **이하**이면 그 가마는 비었으므로 `poll`합니다. 반복해서 끝난 가마를 모두 뺍니다.
3. 이 예약의 끝 시각 `start + dur`을 `offer`합니다. 지금 힙 크기가 "이 시각에 동시에 쓰이는 가마 수"이고, 그 최댓값이 답입니다.

## 주의할 점
- 시각이 10^9, 끝 시각은 2×10^9까지라 시각마다 배열에 +1 하는 방법(차분 배열)은 메모리·시간 모두 불가능합니다. 끝 시각은 `int` 최대(약 2.147×10^9)를 넘지 않지만 `long`으로 두면 마음이 편합니다.
- 예약마다 나머지 전부와 겹치는지 세면 O(n²)이라 20만 개에서 시간 초과입니다.
- 끝과 시작이 맞물린 경우(`끝 == start`)는 겹치지 않으므로 `peek() <= start`(등호 포함)일 때 빼야 합니다. `<`로 쓰면 예 #2에서 2가 나옵니다.
- 시작 시각만 정렬하고 끝 시각을 따로 정렬해 두 포인터로 세는 방법도 O(n log n)으로 맞습니다. 다만 "끝 ≤ 시작"을 먼저 처리하는 순서는 같아야 합니다.

## 복잡도
- 시간 O(n log n), 공간 O(n)
