# 해설 — 이어달리기 바통 전달 시간

## 접근
선수가 최대 8명이므로 달리는 순서는 8! = 40,320가지뿐입니다. 하지만 질문이 20만 개라서 **질문마다 순서를 다시 열거하면** 40,320 × 8 × 200,000 ≈ 6×10^10번 연산으로 시간 초과입니다.

질문은 "`a` 바로 다음 `b`"라는 (순서쌍) 조건뿐이고, 가능한 순서쌍은 `n × (n−1) ≤ 56`개입니다. 그래서 순열을 **한 번만** 열거하면서 답을 표로 만들어 둡니다.

1. 재귀(또는 반복)로 모든 순열을 만듭니다. 각 순열의 총 전달 시간 `cost`를 계산합니다.
2. 그 순열에서 이웃한 모든 쌍 `(order[i], order[i+1])`에 대해 `best[a][b] = min(best[a][b], cost)`로 갱신합니다. 한 순열은 `n−1`개의 이웃 쌍을 가지므로 그 쌍들 각각의 후보가 됩니다.
3. 질문 `[a, b]`의 답은 `best[a][b]`입니다.

## 주의할 점
- 총 전달 시간은 최대 7 × 1,000,000 = 7,000,000이라 `int`로 충분합니다.
- `best`의 초깃값은 충분히 큰 값(`Integer.MAX_VALUE`)으로 두고, `n ≥ 2`, `a ≠ b`이므로 모든 쌍이 어떤 순열에는 반드시 이웃으로 등장해 값이 채워집니다.
- 순열을 만드는 재귀에서 `used[]` 복구(백트래킹)를 잊으면 일부 순열이 빠집니다.

## 복잡도
- 시간 O(n! · n + m) (m = 질문 수), 공간 O(n²)
