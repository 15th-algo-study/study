# 해설 — 꼬치 복원

## 접근
양쪽 끝에만 꽂는 것은 덱에 `addFirst`/`addLast`만 하는 것과 같습니다. 완성된 꼬치에서 그 과정을 **거꾸로** 읽어 냅니다.

**관찰**: `k`번 재료를 꽂은 직후, 꼬치에는 1번부터 `k`번까지가 꽂혀 있고 이들은 완성된 꼬치에서도 **연속한 구간**을 이룹니다(그 뒤에 꽂히는 재료는 모두 이 구간의 바깥쪽에 붙기 때문입니다). 그리고 `k`번은 그 구간의 **양 끝 중 하나**에 있어야 합니다.

따라서 각 번호의 위치 `pos[v]`를 구해 두고, 1번 위치에서 시작하는 구간 `[l, r]`을 번호 순서대로 넓혀 갑니다.

```
l = r = pos[1], 1번은 'L'
for k = 2..n:
    pos[k] == l - 1 이면 'L', l--
    pos[k] == r + 1 이면 'R', r++
    둘 다 아니면 불가능 → ""
```

구간 `[l, r]`에는 정확히 1~`k-1`번이 들어 있으므로 `pos[k]`가 `l-1`과 `r+1` 둘 다일 수는 없고, 답은 유일합니다. 다르게 말하면, 만들 수 있는 꼬치는 1을 기준으로 **왼쪽은 감소, 오른쪽은 증가**하는 골짜기 모양뿐입니다.

## 주의할 점
- 매 단계 `k`의 위치를 배열에서 찾으면 O(n²)입니다. `pos` 배열을 먼저 만드세요.
- n = 10^6 이므로 문자열을 `+=`로 이어 붙이면 O(n²)으로 시간 초과입니다. `char[]`에 채운 뒤 `new String(char[])`로 만드세요.
- 가능한 방법을 모두 시도하는 탐색(2^(n-1)가지)은 n이 조금만 커도 끝나지 않습니다. 관찰로 분기를 없애야 합니다.

## 복잡도
- 시간 O(n), 공간 O(n)
