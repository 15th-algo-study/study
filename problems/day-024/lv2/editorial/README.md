# 해설 — 징검다리 놓기

## 접근
양쪽 끝에 넣고 빼는 것은 덱인데, **"서쪽에서 i번째"** 를 물어보는 것이 문제입니다. `ArrayDeque`는 인덱스 접근을 제공하지 않고, `LinkedList.get(i)`는 O(i), `ArrayList.add(0, v)`는 O(n)이라 100만 명령에서 시간 초과입니다.

**배열로 덱을 직접 만듭니다.** 길이 `2m + 1`(`m` = 명령 수)의 배열을 잡고 가운데에서 시작하면, 서쪽으로 최대 `m`칸, 동쪽으로 최대 `m`칸 늘어나도 배열을 벗어나지 않습니다.

- `head`: 서쪽 끝 돌의 인덱스, `tail`: 동쪽 끝 돌의 **다음** 인덱스. 처음에는 `head = tail = m`.
- 서쪽에 놓기: `buf[--head] = v`
- 동쪽에 놓기: `buf[tail++] = v`
- 서쪽에서 `i`번째: 돌 개수 `tail - head`가 `i` 이상이면 `buf[head + i - 1]`, 아니면 -1
- 서쪽 치우기: 비어 있지 않으면 `head++`. 동쪽 치우기: `tail--`.

모든 명령이 O(1)입니다. 이것이 `ArrayDeque`가 내부적으로 하는 일(원형 버퍼)의 단순화 버전입니다.

## 주의할 점
- 비어 있는지 검사는 `head == tail`입니다. 치울 때 이 검사를 빠뜨리면 `head > tail`이 되어 이후 답이 엉킵니다.
- 종류 3의 `i`가 최대 10^6이므로 `head + i - 1`이 배열 범위를 넘을 수 있습니다. 먼저 개수와 비교하세요.
- 종류 4, 5의 두 번째 값은 의미 없는 값이므로 읽지 마세요.

## 복잡도
- 시간 O(m), 공간 O(m)
