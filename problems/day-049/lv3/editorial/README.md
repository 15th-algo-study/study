# 해설 — 세탁소의 세탁기와 건조기

## 접근
두 기계를 차례로 거치는 작업 순서 문제입니다. 건조기가 노는 시간을 줄이려면 **앞쪽에는 세탁이 짧은 묶음**(건조기가 일찍 일을 시작하도록), **뒤쪽에는 건조가 짧은 묶음**(마지막에 건조기 혼자 남아 도는 시간이 짧도록)이 와야 합니다. 정확한 규칙은 다음과 같습니다.

1. 묶음을 두 그룹으로 나눕니다. A = `wash < dry`인 묶음, B = `wash ≥ dry`인 묶음.
2. A는 `wash` **오름차순**, B는 `dry` **내림차순**으로 정렬합니다.
3. A 다음에 B를 이어 붙인 순서로 처리합니다.

순서가 정해지면 시뮬레이션은 간단합니다. 세탁 끝 시각 `t1 += wash`, 건조 끝 시각 `t2 = max(t2, t1) + dry`를 차례로 계산하면 마지막 `t2`가 답입니다.

### 왜 맞는가 (교환 논법)
이웃한 두 묶음 `x`(앞), `y`(뒤)만 바꿔 봅니다. 두 묶음 앞까지 세탁이 끝난 시각을 `T1`, 건조가 끝난 시각을 `T2`라 하면, 둘 이외 묶음의 시각은 두 묶음이 끝난 뒤의 `(세탁 끝, 건조 끝)`에만 영향을 받습니다. 세탁 끝 시각은 순서와 무관하게 `T1 + w_x + w_y`로 같으므로 **건조 끝 시각**만 비교하면 됩니다.

`x` 다음 `y`일 때 건조 끝 시각은
`max( max(T2, T1 + w_x) + d_x, T1 + w_x + w_y ) + d_y`
입니다. 정리하면 `max(T2 + d_x + d_y, T1 + w_x + d_x + d_y, T1 + w_x + w_y + d_y)`이고, 첫 항은 순서와 무관합니다. 따라서 `x`를 앞에 두는 것이 손해가 아닐 조건은

`max(w_x + d_x + d_y, w_x + w_y + d_y) ≤ max(w_y + d_y + d_x, w_y + w_x + d_x)`

이고, 양변에서 `w_x + w_y + d_x + d_y`를 빼면

**`min(w_x, d_y) ≤ min(w_y, d_x)`**

가 됩니다. 이 조건이 바로 위 규칙과 같습니다.
- `x ∈ A, y ∈ B`: `min(w_x, d_y) ≤ w_x < d_x`, 그리고 `w_y ≥ d_y ≥ min(w_x, d_y)`이므로 성립 → A가 B보다 앞.
- 둘 다 A이고 `w_x ≤ w_y`: 좌변 `min(w_x, d_y) ≤ w_x`. 우변 `min(w_y, d_x)`는 `w_y ≥ w_x`, `d_x > w_x`이므로 `w_x` 이상 → 좌변 ≤ 우변 → A 안에서는 `wash` 오름차순.
- 둘 다 B이고 `d_x ≥ d_y`: 좌변 ≤ `d_y`, 우변 = `min(w_y, d_x) ≥ d_y`(`w_y ≥ d_y`, `d_x ≥ d_y`) → B 안에서는 `dry` 내림차순.

어떤 순서든 이 규칙을 어기는 이웃 쌍을 바꾸면 끝 시각이 늘지 않으므로, 규칙대로 정렬된 순서가 최적입니다.

### 가짜 그리디
- "세탁이 짧은 순", "세탁 + 건조 합이 작은 순", "건조가 긴 순"은 모두 예 #1에서 틀립니다(각각 28, 28, 27). 두 그룹으로 나누는 것이 핵심 관찰입니다.

## 주의할 점
- 끝 시각은 최대 4×10^14라 `long`입니다. `t1`, `t2` 모두 `long`으로 두세요.
- `wash == dry`인 묶음은 A, B 어느 쪽에 넣어도 결과가 같습니다. 여기서는 B에 넣었습니다.
- 모든 순서를 시도하는 완전탐색은 `n!`이라 불가능합니다. 교환 조건 `min(w_x, d_y) ≤ min(w_y, d_x)`를 그대로 비교자로 쓰면 추이성이 보장되지 않아 정렬이 어긋날 수 있으니, 두 그룹으로 나눠 각각 정렬하세요.

## 복잡도
- 시간 O(n log n), 공간 O(n)
