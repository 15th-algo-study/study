# 해설 — 파일 이름 패턴 검색

## 접근
`*`가 많아야 하나라는 점이 핵심입니다. 패턴을 `*` 기준으로 **앞부분 `pre`** 와 **뒷부분 `suf`** 로 나누면, 이름 `name`이 패턴과 맞을 조건은

1. `name.length() >= pre.length() + suf.length()` (`*`가 길이 0 이상을 맡으므로)
2. `name`의 앞 `pre.length()` 글자가 `pre`와 글자별로 맞고 (`?`는 무엇이든 통과)
3. `name`의 뒤 `suf.length()` 글자가 `suf`와 글자별로 맞는다

입니다. 가운데 남은 부분은 `*`가 전부 맡으면 되므로 따로 볼 필요가 없습니다. `*`가 없으면 길이가 같아야 하고 글자별로 전부 맞아야 합니다 (`pre` = 패턴 전체, `suf` = 빈 문자열로 두고 길이 조건을 `==`로 바꾸면 같은 코드로 처리됩니다).

이름마다 O(|name|)이면 전체 O(이름 길이 합 + |pattern|)입니다.

## 주의할 점
- `*`가 맡을 길이를 하나씩 바꿔 가며 전부 시도하면 이름 하나에 O(L²)입니다. 길이 20만짜리 이름이면 4×10^10번이라 시간 초과입니다. `*`는 "앞뒤가 맞으면 가운데는 무조건 맞는다"는 관찰로 한 번에 처리하세요.
- 정규식으로 바꿔(`.*`, `.`) `matches`를 쓰는 풀이는 `.*` 뒤의 글자들이 거의 맞다가 끝에서 틀리는 입력에서 되돌아가기(backtracking)가 폭발해 O(L²)이 됩니다.
- 앞부분과 뒷부분이 **겹치면 안 됩니다.** 길이 조건 1번을 먼저 확인하지 않으면 `"aaa"`가 `"*aaaa"`에 맞는 것으로 잘못 세게 됩니다.
- 글자별 비교에서 `?`는 어떤 글자와도 맞지만, 이름에 나오는 `.`이나 `_`는 패턴의 같은 글자와만 맞습니다.

## 복잡도
- 시간 O(Σ|name| + |pattern|), 공간 O(1) (패턴을 나누는 데 쓰는 문자열 제외)
