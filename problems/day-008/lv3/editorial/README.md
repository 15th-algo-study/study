# 해설 — 글자 섞기 기계

## 접근
`k`가 10억이라 한 번씩 돌려 볼 수 없습니다. 핵심 관찰은 **위치들이 여러 개의 고리(사이클)로 나뉜다**는 것입니다.

위치 `i`에서 출발해 `p[i]`, `p[p[i]]`, … 를 따라가면 언젠가 `i`로 돌아옵니다. 이렇게 만들어진 고리 위의 글자들은 기계를 한 번 돌릴 때마다 고리를 따라 한 칸씩 이동하고, 다른 고리에는 영향을 주지 않습니다. 길이가 `L`인 고리는 `L`번 돌리면 제자리로 돌아오므로, `k`번 돌린 결과는 **`k mod L`번 돌린 결과와 같습니다.**

1. 방문하지 않은 위치 `i`마다 고리 `c[0] = i, c[1] = p[c[0]], …, c[L-1]`을 뽑습니다.
2. 고리 안에서 `c[j]`에 있던 글자는 `k`번 뒤 `c[(j + k) mod L]`로 갑니다. 결과 배열에 그대로 써넣습니다.

모든 위치는 정확히 한 고리에만 속하므로 전체 O(n)입니다.

## 주의할 점
- `k`번 직접 섞으면 O(n·k) = 2×10^14 이라 시간 초과입니다. "순열을 제곱해 가며 `k`를 이진수로 쪼개는" 방법도 O(n log k)로 통과하지만, 고리를 쓰면 더 간단합니다.
- `(j + k) mod L`에서 `j + k`는 최대 약 10^9 + 2×10^5 이므로 `int`로도 넘치지 않지만, `k`를 먼저 `L`로 나눈 나머지로 줄여 두면 안전합니다.
- 글자가 가는 방향에 주의하세요. 문제는 "`i`번에 있던 글자가 `p[i]`번으로 간다"이므로 `result[p[i]] = s[i]`입니다. 반대로 `result[i] = s[p[i]]`로 쓰면 역방향으로 섞은 결과가 되어 틀립니다. 예 #1의 `"abcd"` → `"dabc"`로 방향을 확인하세요.
- 결과는 `char[]`에 채운 뒤 `new String(char[])`로 만드세요. `+=`로 이어 붙이면 O(n²)입니다.

## 복잡도
- 시간 O(n), 공간 O(n)
