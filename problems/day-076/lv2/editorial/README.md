# 해설 — 우편 수송망

## 접근
간선 가중치(시간)가 모두 양수인 그래프에서 한 출발점으로부터의 최단 거리이므로 **다익스트라**입니다.

1. 간선을 출발 정점별로 모읍니다. 정점 30만, 간선 50만이라 `List<int[]>[]`보다 **CSR(압축 인접 배열)** 이 빠르고 메모리도 적습니다.
   - `head[v]`: v에서 나가는 간선이 `edges` 배열의 어디부터 시작하는지 (출발 정점별 개수를 센 뒤 누적합)
2. `dist[start] = 0`, 나머지는 INF. 우선순위 큐에 `(거리, 정점)`을 넣고 가장 가까운 것부터 꺼냅니다.
3. 꺼낸 거리가 `dist[v]`보다 크면 이미 더 짧게 확정된 **오래된 항목**이므로 건너뜁니다(지연 삭제).
4. `v`의 간선 `(v → u, w)`마다 `dist[v] + w < dist[u]`이면 갱신하고 큐에 넣습니다.
5. 끝까지 INF인 정점은 -1로 바꿉니다.

음수 간선이 없으므로 큐에서 처음 꺼낸 순간 그 정점의 거리가 확정됩니다. 그래서 각 정점의 간선은 한 번씩만 살펴봅니다.

## 주의할 점
- 거리는 최대 (n − 1) × 10^9 ≈ 3 × 10^14 이므로 `long`이어야 합니다. 예 #2처럼 노선 하나만으로도 10억이고, 두 개를 이으면 `int`를 넘습니다.
- 큐에서 꺼낸 항목이 오래된 것인지 확인하지 않으면, 같은 정점의 간선을 여러 번 훑게 되어 최악의 경우 매우 느려집니다.
- 큐 없이 "아직 확정되지 않은 정점 중 최솟값"을 배열에서 매번 찾는 O(n²) 다익스트라는 n = 30만에서 9 × 10^10번 비교라 시간 초과입니다.
- 벨만–포드(모든 간선을 n − 1번 완화)도 O(n·m)이라 최단 경로가 정점 수만큼 긴 입력에서 시간 초과입니다.

## 복잡도
- 시간 O((n + m) log m), 공간 O(n + m)
