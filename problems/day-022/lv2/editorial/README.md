# 해설 — 병원 접수 대기열

## 접근
큐의 **가운데**에서 환자를 빼야 하는 것이 문제입니다. `LinkedList.remove(Object)`나 `ArrayList.remove`로 실제로 빼면 한 번에 O(n)이라, 대기열이 수십만 명일 때 시간 초과입니다.

**지연 삭제(lazy deletion)** 를 씁니다. 나간 환자를 큐에서 당장 지우지 않고 "나갔다"고 표시만 해 두었다가, 호출 때 맨 앞이 이미 나간 환자면 건너뜁니다.

1. `waiting[id]`: 지금 대기 중인지.
2. `[1, id]`: `waiting[id]`가 거짓일 때만 참으로 바꾸고 큐에 넣습니다.
3. `[2, id]`: `waiting[id]`를 거짓으로 바꿉니다. 큐는 건드리지 않습니다.
4. `[3, x]`: 큐 맨 앞부터 꺼내면서 **유효한** 항목이 나올 때까지 버립니다. 유효하면 `waiting`을 거짓으로 바꾸고 기록합니다.

**함정 — 오래된 항목**: 환자 1이 줄을 섰다가 나가고 다시 서면 큐에는 1이 **두 번** 들어 있고, 앞쪽 것은 이미 무효입니다. `waiting[1]`만 보면 앞쪽의 낡은 항목을 유효하다고 착각해 순서가 틀립니다(예 #3). 그래서 큐에는 `id`가 아니라 **몇 번째 사건(event index)으로 들어왔는지**를 넣고, `latest[id]`에 그 환자의 가장 최근 입장 사건 번호를 기록합니다. 꺼낸 항목 `e`가 유효하려면 `waiting[id] && latest[id] == e` 여야 합니다.

큐에 들어가는 항목은 사건 수 이하이고 각 항목은 한 번만 꺼내지므로 전체 O(n)입니다.

## 주의할 점
- 종류 3의 두 번째 값은 의미가 없습니다. 생성된 큰 입력에는 아무 값이나 들어 있습니다.
- 호출 결과 개수를 미리 모르므로 리스트에 모으거나, 종류 3의 개수를 먼저 세어 배열을 만듭니다.
- `id`가 최대 10^6이므로 `boolean[1_000_001]`, `int[1_000_001]` 정도의 배열은 부담 없습니다.

## 복잡도
- 시간 O(n), 공간 O(n + max id)
