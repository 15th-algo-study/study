# 해설 — 왕국 나누기

## 접근
지문대로 재귀하면 "구간에서 최댓값 찾기 → 둘로 나누기"를 반복합니다. 높이가 오름차순이면 매번 맨 오른쪽에서 갈라져 구간 길이가 1씩만 줄어들어 O(n²)이고, 재귀 깊이도 n이 됩니다. 30만 칸에서는 시간 초과입니다.

**관찰: 비용을 성 기준이 아니라 칸 기준으로 셉니다.** `i`번 칸에 성이 세워지는 순간의 구간을 생각하면, 그 구간은

- 왼쪽으로는 `heights[j] ≥ heights[i]`인 가장 가까운 `j`(= `L`) 직전까지,
- 오른쪽으로는 `heights[j] > heights[i]`인 가장 가까운 `j`(= `R`) 직전까지

입니다. 그 바깥의 더 높은(또는 왼쪽의 같은 높이) 칸이 먼저 성이 되어 `i`를 그쪽과 갈라놓기 때문이고, 안쪽의 칸들은 모두 `i`보다 낮거나(같다면 오른쪽에 있어) `i`보다 먼저 성이 될 수 없기 때문입니다. 따라서

> 답 = Σ `heights[i] × (R − L − 1)`

`L`, `R`은 **단조 스택**으로 한 번에 구합니다. 왼쪽에서 오른쪽으로 보며 스택에 인덱스를 쌓되, 현재 높이보다 **낮은** 것을 모두 꺼냅니다. 꺼낸 칸들의 `R`은 현재 칸이고, 다 꺼낸 뒤 스택 꼭대기가 현재 칸의 `L`입니다(같은 높이는 꺼내지 않으므로 왼쪽의 같은 높이가 `L`이 됩니다).

## 주의할 점
- 같은 높이 처리: 왼쪽은 `≥`로 막고 오른쪽은 `>`로 막아야 "가장 왼쪽 최댓값" 규칙과 맞습니다. 둘 다 `>`로 하면 `[2, 2, 2]`에서 틀립니다.
- 곱셈은 `long`입니다. `(R - L - 1)`이 30만, 높이가 10^8이면 한 항이 3×10^13, 합은 최대 4.5×10^18까지 갑니다.
- 재귀로 그대로 구현하면 정렬된 입력에서 깊이 n의 재귀가 됩니다. 이 러너는 스택이 넉넉해 StackOverflowError는 나지 않지만 O(n²)라 시간 초과입니다. `large_01`(오름차순)과 `large_02`(모두 같은 높이)가 이를 걸러냅니다.
- 값이 큰 순서로 정렬해 TreeSet으로 양옆 경계를 찾는 O(n log n) 풀이도 가능합니다.

## 복잡도
- 시간 O(n), 공간 O(n)
